How Windows 10 Handles DNS over HTTPS Lookups

DNS over HTTPS (DoH) in Windows 10 allows the operating system to encrypt traditional, plaintext Domain Name System queries by wrapping them inside standard HTTPS traffic over port 443. This article outlines how Windows 10 implements DoH at the system level via the native DNS client service, how it maps standard IP addresses to secure endpoints, the lookup modes available to users, and how queries are processed across the entire operating system.

The Role of the Native DNS Client

Prior to system-level DoH implementation, DNS queries were handled either unencrypted by the Windows operating system over UDP/TCP port 53, or individually encrypted by specific applications like web browsers running their own custom network stacks.

Windows 10 integrates DoH directly into its core DNS Client service (Dnscache). By handling encryption at the OS level, every outbound network request—whether originating from a background system service, a command-line utility, or a standard web browser—automatically routes through the secure, encrypted DNS pipeline without requiring separate, per-application configuration.

Auto-Promotion and the DoH Mapping Table

Windows 10 does not require users to manually specify full HTTPS URLs (DoH templates) in standard configuration interfaces. Instead, the OS uses an internal mapping table that correlates well-known, trusted DNS resolver IP addresses to their corresponding HTTPS endpoints.

For example, when a user assigns known public resolvers such as Cloudflare (1.1.1.1), Google (8.8.8.8), or Quad9 (9.9.9.9), Windows 10 detects the matching server IP and automatically links it to the appropriate secure URL. Administrators can also add custom DoH mappings for internal or private enterprise resolvers using the netsh dns add encryption command or PowerShell cmdlets.

Lookup Modes and Encryption Enforcement

Windows 10 evaluates and executes DNS lookups based on three distinct policy states configured per network interface:

  • Encrypted Only: The system enforces strict security. Windows 10 will only query the specified DNS server over HTTPS. If the encrypted connection fails—due to network filtering, server unavailability, or certificate mismatches—the DNS resolution fails entirely. It will not fall back to unencrypted transmission, preventing accidental exposure of queried domains.
  • Encrypted Preferred (Opportunistic): The OS attempts to establish a secure DoH connection first. If the resolver does not respond over HTTPS, or if the initial TLS handshake fails, the DNS Client automatically falls back to standard, unencrypted DNS over port 53.
  • Unencrypted Only: The OS bypasses DoH entirely and issues conventional plaintext DNS requests over port 53.

The Query Lifecycle in Windows 10

When an application initiates a network connection to a domain name, Windows 10 executes the lookup through the following sequence:

  1. Local Cache Check: The Dnscache service first verifies whether the record already exists in the local DNS cache. If found, the resolved IP address is returned instantly.
  2. Protocol Selection: If the record must be fetched externally, the DNS Client checks the configuration for the active network adapter to determine if an encrypted resolver is configured.
  3. Connection Establishment: If DoH is active, Windows establishes an HTTP/2 or HTTP/1.1 connection secured with TLS to the mapped DoH server over port 443.
  4. Query Transmission: The DNS request payload is formatted as a binary DNS message (content-type: application/dns-message) inside an HTTP POST or GET request.
  5. Payload Decryption and Response: The resolver processes the request and sends the encrypted response back over the established TLS tunnel. The Windows DNS Client decrypts the payload, updates the local cache, and passes the resolved IP address back to the requesting application.

Enterprise and Administrative Control

In managed network environments, Windows 10 provides administrative controls to prevent or enforce DoH behavior. Network administrators can control DNS encryption using Group Policy or Mobile Device Management (MDM) policies. Through the policy path Computer Configuration > Administrative Templates > Network > DNS Client > Configure DNS over HTTPS (DoH) name resolution, administrators can explicitly mandate encryption, allow fallbacks, or disable DoH entirely to maintain compatibility with internal DNS inspection and filtering appliances.
