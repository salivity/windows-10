How Windows 10 Processes GPO Precedence at Boot

When a Windows 10 device boots up, it initializes its system environment by applying computer-specific Group Policy Objects (GPOs) prior to user logon. The operating system follows a strictly defined hierarchical order commonly known as LSDOU (Local, Site, Domain, and Organizational Unit), applying a "last writer wins" methodology to resolve conflicting settings. Understanding this boot-time evaluation path, alongside critical modifiers like policy enforcement, inheritance blocking, and network initialization, is essential for diagnosing why specific machine configurations take effect.

The Standard Boot Processing Order (LSDOU)

During the boot sequence, Windows 10 queries Active Directory Domain Services (AD DS) to identify the machine's location in the directory tree and processes computer-level policies in the following sequence:

  1. Local Group Policy: The system first processes the local policy stored directly on the Windows 10 machine. Because it is evaluated first, its settings are the most easily overwritten.
  2. Site: The system evaluates GPOs linked to the Active Directory Site where the computer's subnet resides.
  3. Domain: The system evaluates GPOs linked directly at the Active Directory domain root.
  4. Organizational Unit (OU): The system evaluates GPOs linked to the computer's specific OU. If the device is inside nested OUs, Windows 10 processes the parent OU first, moving down the tree to the innermost child OU containing the computer account.

Under standard processing rules, policies applied later in this sequence overwrite identical settings applied earlier. Therefore, settings defined at the child OU level possess the highest natural precedence.

Synchronous vs. Asynchronous Boot Processing

Windows 10 implements Fast Startup and Fast Logon Optimization by default, which changes how boot policies are handled:

  • Asynchronous Processing (Default): The boot process does not wait for the network to fully initialize before loading the sign-in screen. Group Policy executes in the background, which may delay the application of newly configured policies or machine startup scripts until a subsequent reboot.
  • Synchronous Processing: If specific policy types are detected—such as software installation policies, folder redirection, or direct startup scripts—or if the administrator enables the "Always wait for the network at computer startup and logon" policy, Windows 10 pauses the boot sequence until the network stack initializes, GPOs are retrieved, and settings are fully applied before presenting the login screen.

GPO Rule Modifiers and Exceptions

The standard LSDOU precedence order can be modified by specific Active Directory administrative controls:

  • Enforced: A GPO set to "Enforced" (formerly "No Override") cannot be blocked by downstream containers and always takes precedence over conflicting settings in lower-level OUs. If multiple GPOs are enforced, the one highest in the Active Directory hierarchy wins.
  • Block Inheritance: An OU can be configured to block policy inheritance from parent OUs, domains, or sites. However, an "Enforced" GPO from a higher level will bypass this block.
  • Link Order: When multiple GPOs are linked to the same container (such as a single OU), they are processed in reverse order of their Link Order number. Link Order 1 has the highest priority and is processed last, overriding Link Order 2, 3, and so on.
  • WMI and Security Filtering: After precedence is established, Windows 10 filters the policy list. If the computer account lacks "Read" and "Apply Group Policy" permissions, or fails a specified WMI query (such as OS architecture or build checks), the GPO is bypassed entirely.

Startup Scripts and Loopback Processing

Before the Windows 10 desktop environment or login prompt becomes accessible, the system executes any startup scripts assigned through the processed Computer Configuration nodes. These run sequentially under the NT AUTHORITY\SYSTEM account.

If Group Policy Loopback Processing is enabled on the computer, Windows 10 performs an additional step at boot: it re-evaluates User Configuration policies based on the computer's location in Active Directory rather than the user's location, either replacing the user's standard policies or merging with them during subsequent user login.
