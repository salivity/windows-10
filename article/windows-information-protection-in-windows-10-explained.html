Windows Information Protection in Windows 10 Explained

Windows Information Protection (WIP), formerly known as Enterprise Data Protection (EDP), is a built-in framework in Windows 10 designed to prevent accidental enterprise data leakage without compromising the user experience. By operating at the operating system level, WIP separates personal and corporate data, enforces encryption, and restricts unauthorized apps and network locations from accessing sensitive enterprise assets. This article explains the underlying mechanisms Windows 10 uses to implement, manage, and enforce the WIP framework.

Dual-Identity Architecture

Windows 10 implements WIP through a dual-identity model that differentiates between personal and corporate data on the same device. When an enterprise policy is deployed, the OS associates specific enterprise identities (typically corporate domains or Azure Active Directory tenants) with corporate resources.

Files, emails, and clipboard content are tagged with an enterprise identity. Because this tagging happens natively within the file system and memory management layers, users do not need to switch profiles or containers to separate work from personal tasks; the OS determines the data's classification automatically based on its source.

File-Level Encryption via EFS

WIP leverages the existing Windows Encrypting File System (EFS) architecture to secure corporate files at rest. When a file is identified as corporate—whether downloaded from a corporate SharePoint site, attached to an enterprise email, or generated by an enterprise application—Windows 10 automatically encrypts it using EFS.

The encryption keys are tied to the enterprise identity and managed via the organization’s Mobile Device Management (MDM) infrastructure or Azure Active Directory. If an employee leaves the company or a device is reported lost, an administrator can trigger a remote wipe that revokes the encryption keys, rendering the enterprise data unreadable while leaving personal files intact.

App Classification: Enlightened vs. Unenlightened

Windows 10 categorizes applications into two distinct groups to enforce WIP policies:

  • Enlightened Apps: These applications are aware of WIP and can discern between corporate and personal data. They utilize WIP APIs to query the context of the data being handled. For example, Microsoft Word can allow a user to open a personal document and a corporate document simultaneously, applying encryption and data-sharing restrictions exclusively to the corporate file.
  • Unenlightened Apps: These applications cannot distinguish between work and personal data. Windows 10 handles unenlightened apps based on enterprise policy. If an unenlightened app is placed on the allowed enterprise list, the OS treats all files opened or created by that app as corporate data and encrypts them automatically. If it is not on the allowed list, the OS prevents it from accessing any corporate-tagged files.

Network Perimeter Isolation

WIP enforces data protection by monitoring and controlling network boundaries. Administrators define corporate network endpoints, such as internal IP ranges, enterprise cloud domains (e.g., Office 365, internal intranets), and proxy servers.

When Windows 10 connects to an endpoint defined within the corporate boundary, any data retrieved over that connection is automatically tagged as enterprise data and encrypted upon arrival. Conversely, WIP prevents corporate data from being transmitted to untrusted network destinations unless explicitly authorized.

Clipboard and Data Transfer Controls

To prevent data leakage through copy-and-paste actions or drag-and-drop operations, Windows 10 mediates data transfers at the OS level:

  • Block: The OS strictly prevents users from copying corporate data into personal apps or unapproved web forms.
  • Override: The OS prompts the user with a warning that the action is not recommended. If the user chooses to proceed, the action is permitted and an audit event is logged.
  • Silent: The OS permits the transfer without interrupting the user, but silently logs the event for administrative auditing.
  • Off: WIP protection and logging are disabled.

Management via Configuration Service Providers (CSP)

Windows 10 implements WIP policies using the EnterpriseDataProtection Configuration Service Provider (CSP). Management platforms, such as Microsoft Intune or Microsoft Endpoint Configuration Manager, communicate with this CSP via the Windows 10 MDM protocol. The CSP translates the centralized policy settings into local OS configurations, controlling local encryption keys, allowed application lists, network definitions, and audit rules directly within the Windows kernel and subsystem services.
