How Miracast Display Projection Works in Windows 10

Windows 10 includes native support for Miracast, a peer-to-peer wireless screencasting standard that allows users to project their display to compatible external monitors, TVs, or projectors without physical cables. The operating system handles this process by coordinating the graphics subsystem, wireless network drivers, and media encoding engines. By establishing a direct, local Wi-Fi connection between the PC and the receiver, Windows 10 can duplicate or extend the desktop while maintaining low-latency video and audio transmission.

System Requirements and Driver Foundation

For Windows 10 to initiate Miracast projection, the host machine requires compatible hardware and driver architecture:

  • Display Driver: The graphics adapter must support the Windows Display Driver Model (WDDM) 1.3 or higher, which includes built-in APIs for Miracast video pipeline encoding.
  • Wireless Driver: The Wi-Fi adapter must support Network Driver Interface Specification (NDIS) 6.30 or higher and feature native support for Wi-Fi Direct.

Connection Establishment via Wi-Fi Direct

When a user opens the "Project" menu (via Windows Key + P) and selects "Connect to a wireless display," Windows 10 initiates the following sequence:

  1. Device Discovery: Windows uses Wi-Fi Direct device discovery (based on IEEE 802.11 standards) to scan for nearby Miracast receivers (sinks) emitting beacon frames, bypassing the need for a local Wi-Fi router.
  2. Handshake and Pairing: Once a target display is selected, Windows 10 initiates a Wi-Fi Protected Setup (WPS) handshake to establish a secure, peer-to-peer Wi-Fi Direct link (P2P group) between the PC and the display device.
  3. Capability Negotiation: The devices use Real-Time Streaming Protocol (RTSP) over TCP to negotiate supported video resolutions, frame rates, audio formats, and encryption protocols.

Video Processing, Encoding, and Streaming

After the connection is negotiated, Windows 10 routes desktop output through a dedicated hardware-accelerated pipeline:

  • Capture: The Desktop Window Manager (DWM) captures the primary or extended display surface.
  • Encoding: The captured frames are compressed in real time using the H.264 video codec, typically offloaded to hardware encoders built into the GPU (such as Intel Quick Sync, Nvidia NVENC, or AMD AMF) to minimize CPU usage and latency. Audio is simultaneously encoded using AAC or LPCM.
  • Content Protection: If protected media (such as DRM-protected video) is being streamed, Windows 10 applies High-bandwidth Digital Content Protection (HDCP) 2.x over the link.
  • Packetization and Transport: The multiplexed audio/video stream is wrapped into an MPEG-2 Transport Stream (MPEG-TS) container and transmitted to the receiver over User Datagram Protocol (UDP) via the Wi-Fi Direct connection.

Display Modes and User Input Back Channel (UIBC)

Windows 10 treats the Miracast receiver as an additional physical monitor, allowing the user to select between "Duplicate," "Extend," or "Second screen only" via the standard display settings.

Additionally, Miracast in Windows 10 supports the User Input Back Channel (UIBC). If the external display is a touchscreen, interactive whiteboard, or has a connected keyboard and mouse, UIBC routes input signals from the receiver back to the Windows 10 PC over the same wireless link, enabling bidirectional interaction with the host operating system.
