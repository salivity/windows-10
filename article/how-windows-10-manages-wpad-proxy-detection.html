How Windows 10 Manages WPAD Proxy Detection

This article explains how the Microsoft Windows 10 operating system uses the Web Proxy Auto-Discovery (WPAD) protocol to automate proxy configuration. It details the step-by-step discovery sequence using DHCP and DNS, examines how the operating system downloads and executes Proxy Auto-Configuration (PAC) files, and highlights the security controls Windows 10 enforces to prevent common WPAD-related vulnerabilities.

The WPAD Detection Workflow

When the "Automatically detect settings" option is enabled in Windows 10 (located under Settings > Network & Internet > Proxy), network-aware applications relying on the WinINet or WinHTTP APIs trigger an automatic discovery process. Windows 10 attempts to find the URL of a PAC file (typically named wpad.dat) using two primary network mechanisms, executed in a strict order:

  1. DHCP Discovery (Option 252)
    Windows 10 first queries the local DHCP server by sending an inform packet requesting DHCP Option 252. If the network’s DHCP server is configured with Option 252, it returns the direct URL pointing to the wpad.dat configuration file (e.g., http://proxy.corp.example.com/wpad.dat). If this succeeds, the process skips DNS entirely.

  2. DNS Fallback Resolution
    If DHCP Option 252 is unavailable or unconfigured, Windows 10 falls back to standard DNS lookups. The system constructs a query by appending wpad to the primary DNS suffix of the client machine. For instance, if a machine belongs to sub.corp.contoso.com, Windows 10 attempts to resolve:

    • wpad.sub.corp.contoso.com
    • wpad.corp.contoso.com
    • wpad.contoso.com

    Windows 10 will stop navigating up the domain tree once it reaches a top-level domain (TLD) or a domain listed on the system's internal Domain Suffix Search Order list to prevent querying public namespaces.

Fetching and Executing the PAC File

Once Windows 10 identifies a valid WPAD URL, the system performs the following actions:

  • HTTP GET Request: Windows sends an HTTP request to the designated server and port (usually port 80) to download wpad.dat.
  • MIME-Type and Content Verification: The downloaded file contains JavaScript functions, predominantly FindProxyForURL(url, host).
  • Sandboxed Execution: Windows 10 routes outbound connection targets through this JavaScript function. The script evaluates the destination URL or IP address against defined rules (such as subnets, internal hostnames, or specific IP ranges) and outputs PROXY proxy_address:port or DIRECT (bypass proxy).

Security Enhancements in Windows 10

Historically, WPAD was susceptible to credential harvesting, man-in-the-middle (MitM) attacks, and remote code execution. Windows 10 implements several security mechanisms to mitigate these risks:

  • Disabling LLMNR and NetBIOS for WPAD: Earlier Windows versions fell back to broadcast protocols (Link-Local Multicast Name Resolution and NetBIOS over TCP/IP) if DNS failed, allowing local attackers to spoof WPAD responses. Windows 10 blocks LLMNR and NetBIOS lookups exclusively for WPAD resolution, forcing reliance strictly on secure DHCP and unicast DNS.
  • PAC Script Sandboxing: In modern versions of Windows 10, the PAC parsing engine runs inside an isolated, out-of-process sandbox (pacjscript.dll or within constrained app containers) with reduced privileges, preventing memory corruption exploits inside the PAC parser from compromising system-level processes.
  • Strict Host Header Checks: Windows 10 requires the web server hosting the wpad.dat file to validate host headers to ensure requests are not being manipulated by local attackers attempting DNS rebinding.

Managing and Disabling WPAD

WPAD can be managed across an organization using standard administrative tools:

  • Graphical Interface: Users can manually toggle "Automatically detect settings" in the modern Settings app or via inetcpl.cpl under the Connections tab.
  • Group Policy: Administrators can enforce or disable WPAD across the domain by navigating to:
    User Configuration or Computer Configuration > Administrative Templates > Windows Components > Internet Explorer > Prevent enabling proxy settings or by configuring WinHTTP proxy policies via command-line utilities like netsh winhttp.
