Windows 10 MTU Configuration for Network Adapters

The Microsoft Windows 10 operating system manages Maximum Transmission Unit (MTU) sizes by applying default protocol baselines per interface type, dynamically optimizing packet sizes through Path MTU Discovery (PMTUD), and allowing manual administrative overrides. By default, Windows standardizes standard Ethernet traffic to 1500 bytes, adjusts downward for tunneling protocols, and maintains these configurations through its TCP/IP stack (tcpip.sys) and the Windows Registry.

Default MTU Assignment

When a network adapter is initialized in Windows 10, the operating system assigns a default MTU based on the underlying link-layer technology:

  • Ethernet and Wi-Fi: Standardized at 1500 bytes, which aligns with IEEE 802.3 specifications.
  • PPPoE Connections: Automatically reduced to 1492 bytes to accommodate the 8-byte PPPoE header.
  • VPN Adapters: Dynamically lowered (often between 1200 and 1400 bytes) depending on the encapsulation protocol (e.g., WireGuard, IPsec, OpenVPN) to prevent packet fragmentation caused by outer IP headers.
  • Loopback Interface: Configured with a large buffer (typically 65535 bytes for IPv4 and 4294967295 bytes for IPv6) because packets never leave local system memory.

Dynamic Adjustment: Path MTU Discovery (PMTUD)

Windows 10 implements Path MTU Discovery by default as defined by RFC 1191 (IPv4) and RFC 8201 (IPv6). Rather than transmitting all packets at the static adapter MTU, the TCP/IP stack operates as follows:

  1. Windows sets the Don't Fragment (DF) bit in the IP header of outgoing packets.
  2. If an intermediate router along the network path has a smaller MTU than the packet size, the router drops the packet and responds with an ICMP Type 3, Code 4 message ("Destination Unreachable, Fragmentation Needed and DF Set"), specifying the next-hop MTU.
  3. Windows 10 receives this ICMP packet and lowers the MTU for that specific route in its local cache.
  4. If network configurations block ICMP messages (creating a "Black Hole" router), modern Windows 10 builds feature MTU Black Hole Detection, which automatically lowers the MTU when connection attempts fail to receive acknowledgments despite repeated transmissions.

Checking the Current MTU

To view the currently configured MTU across all active network adapters, Windows provides two native command-line methods:

Using Netsh via Command Prompt:

netsh interface ipv4 show subinterfaces

(Replace ipv4 with ipv6 to view IPv6 MTU sizes).

Using PowerShell:

Get-NetIPInterface | Select-Object InterfaceAlias, AddressFamily, NlMtuBytes

Manual Configuration

Administrators can manually override automatic MTU negotiation when dealing with specific ISP constraints, tunneling requirements, or jumbo frames.

Using Netsh:

netsh interface ipv4 set subinterface "Ethernet" mtu=1450 store=persistent

The store=persistent flag ensures the value remains after system reboots. Omitting it applies the change only until the next restart (store=active).

Using PowerShell:

Set-NetIPInterface -InterfaceAlias "Ethernet" -NlMtuBytes 1450

Registry Storage

When an MTU value is manually configured or permanently modified by network drivers, Windows stores it within the registry under the interface's unique Globally Unique Identifier (GUID):

HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\Tcpip\Parameters\Interfaces\{Adapter-GUID}

A DWORD (32-bit) value named MTU defines the static size in bytes. If this registry entry does not exist, Windows 10 relies on the standard dynamic defaults provided by the driver and the network stack.
