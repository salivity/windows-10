How Windows 10 Handles ipconfig /flushdns

This article explains how the Microsoft Windows 10 operating system processes the ipconfig /flushdns command to clear its local Domain Name System (DNS) resolver cache. It covers the underlying role of the DNS Client service, the distinction between volatile memory storage and static host files, and the step-by-step internal process Windows executes to remove outdated network records and restore direct querying to external DNS servers.

The Role of the DNS Resolver Cache

When a user visits a website or connects to a networked resource, Windows 10 queries a DNS server to translate human-readable domain names (such as example.com) into numerical IP addresses. To reduce latency and network traffic, the operating system saves these successful resolutions—as well as failed lookup attempts (negative caching)—in volatile memory (RAM). This repository is managed by a background system component known as the DNS Client service (Dnscache).

What Happens When You Run ipconfig /flushdns

Executing ipconfig /flushdns in an administrative Command Prompt or Windows PowerShell triggers a direct command to the DNS Client service. The sequence occurs as follows:

  1. Invocation: The ipconfig.exe utility is executed with the /flushdns parameter.
  2. Inter-Process Communication: ipconfig.exe issues a Remote Procedure Call (RPC) to the active Dnscache service running in the background.
  3. Cache Purging: Upon receiving the directive, the DNS Client service clears all dynamically stored resource records from RAM. This includes:
    • Host records (A and AAAA)
    • Alias records (CNAME)
    • Mail exchange records (MX)
    • Negative cache entries (temporary records of domains that failed to resolve)
  4. Preservation of Static Entries: The command does not alter or delete the static mappings located in the local hosts file (C:\Windows\System32\drivers\etc\hosts). Entries in this file remain intact and are immediately re-read into the active memory table.
  5. Confirmation: Once the memory pointers to the cached records are reset, the utility outputs the confirmation message: "Successfully flushed the DNS Resolver Cache."

Why the Flush Is Necessary

Under normal operations, records in the DNS cache expire automatically based on their Time to Live (TTL) value, which is set by the authoritative DNS server for that domain. However, manual cache flushing is required in several common scenarios:

  • Stale Records: If a web server changes IP addresses before the local TTL expires, Windows 10 will continue attempting to connect to the old IP, causing connection errors.
  • DNS Spoofing and Poisoning: If corrupt or malicious entries are injected into the local cache, flushing eliminates those entries immediately.
  • Network Troubleshooting: Clearing the cache ensures that all subsequent network requests bypass local data and fetch fresh records directly from the configured upstream DNS servers.

After the flush completes, the next attempt to reach any domain forces Windows 10 to perform a full external DNS lookup, repopulating the cache with updated records.
