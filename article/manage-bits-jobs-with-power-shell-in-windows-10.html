Manage BITS Jobs with PowerShell in Windows 10

The Microsoft Windows 10 operating system manages asynchronous, prioritized file transfers using the Background Intelligent Transfer Service (BITS), which can be fully controlled through Windows PowerShell. By utilizing the built-in BitsTransfer module, administrators and users can create, monitor, pause, resume, and finalize background file downloads and uploads. BITS optimizes network usage by leveraging idle bandwidth, ensuring that foreground applications are not impacted, and automatically recovers file transfers after network interruptions or system reboots.

The BitsTransfer PowerShell Module

Windows 10 includes the BitsTransfer module by default. It provides a set of cmdlets designed to interact directly with the BITS Windows service, supporting file transfers over HTTP, HTTPS, and SMB.

The primary cmdlets include:

  • Start-BitsTransfer
  • Get-BitsTransfer
  • Suspend-BitsTransfer
  • Resume-BitsTransfer
  • Set-BitsTransfer
  • Complete-BitsTransfer
  • Remove-BitsTransfer
  • Add-BitsFile

Initiating File Transfers

The simplest way to initiate a transfer is with Start-BitsTransfer. By default, this cmdlet runs synchronously, blocking the PowerShell console until the transfer is finished.

Start-BitsTransfer -Source "https://example.com/file.iso" -Destination "C:\Downloads\file.iso"

To run the job in the background, use the -Asynchronous parameter. This immediately returns control to the PowerShell session and outputs a BITS job object.

Start-BitsTransfer -Source "https://example.com/file.iso" -Destination "C:\Downloads\file.iso" -Asynchronous

Monitoring Active Jobs

Asynchronous transfers run as background jobs managed by the operating system. You can inspect the status, progress, and error states of all active jobs using Get-BitsTransfer:

Get-BitsTransfer

To view detailed progress, including the bytes transferred and current transfer rate, pipeline the job into Format-List:

Get-BitsTransfer | Format-List -Property JobId, DisplayName, JobState, BytesTotal, BytesTransferred

Possible job states include Connecting, Transferring, Transferred, Suspended, and Error.

Managing Job States

BITS allows dynamic job control to adapt to network availability or user needs:

  • Pausing a Job: Temporarily halt a transfer using Suspend-BitsTransfer.

    Get-BitsTransfer | Suspend-BitsTransfer

  • Resuming a Job: Continue a suspended or interrupted transfer using Resume-BitsTransfer.

    Get-BitsTransfer | Resume-BitsTransfer

  • Canceling a Job: Discard a transfer and remove temporary files with Remove-BitsTransfer.

    Get-BitsTransfer | Remove-BitsTransfer

Finalizing Transfers

When an asynchronous transfer finishes downloading, its state changes to Transferred, but the file is not yet accessible at the target path. BITS holds the file in a temporary state until it is explicitly finalized.

To complete the process and make the file available in its target directory, execute Complete-BitsTransfer:

Get-BitsTransfer -JobState Transferred | Complete-BitsTransfer

If this command is not run, the file will remain hidden in a temporary cache and will eventually be purged if the job expires.

Configuring Priority and Bandwidth Usage

Windows 10 determines how aggressively BITS uses network bandwidth through priority levels: Foreground, High, Normal, and Low.

  • Foreground: Transfers run with highest priority and compete directly with other active network traffic.
  • Normal / Low: Transfers use only idle network bandwidth.

Priority can be defined at creation or modified on an existing job:

# Set priority during creation
Start-BitsTransfer -Source "https://example.com/update.msu" -Destination "C:\Updates\update.msu" -Priority High -Asynchronous

# Modify an active job
Get-BitsTransfer | Set-BitsTransfer -Priority Low

Using these cmdlets, Windows 10 gives administrators programmatic, fine-grained control over network-resilient downloads and administrative payload deployments.
