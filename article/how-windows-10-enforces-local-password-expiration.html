How Windows 10 Enforces Local Password Expiration

This article explains how the Microsoft Windows 10 operating system manages and enforces password expiration policies for local user accounts. Windows 10 relies on local policy configurations, system services, and account metadata stored in the Security Accounts Manager database to track password age, warn users of impending expiration, and block access until an expired password is updated.

The Security Accounts Manager (SAM) Database

Local account details are stored locally within the Security Accounts Manager (SAM) database in the Windows registry. For every local user, the SAM records specific attributes alongside the password hash, including:

  • Password Last Set Timestamp: The exact date and time the user's password was last modified.
  • User Account Control Flags: Attributes that dictate account behavior, such as the DONT_EXPIRE_PASSWORD flag (commonly seen as the "Password never expires" checkbox in administration consoles).

Policy Configuration

Password expiration rules are determined via the Windows Local Security Policy (secpol.msc) under Account Policies > Password Policy. The primary setting governing this behavior is the Maximum password age:

  • Default Behavior: On standalone Windows 10 installations, the default maximum password age is often set to 0, which disables expiration.
  • Active Expiration: When configured to a value between 1 and 998 days, Windows activates expiration tracking for all local accounts that do not have the "Password never expires" exception enabled.

Administrators can also configure these thresholds using the Command Prompt via the net accounts /maxpwage:<days> command or through PowerShell.

Enforcement via LSASS During Authentication

The enforcement process occurs at logon and is handled by the Local Security Authority Subsystem Service (LSASS):

  1. Authentication Request: When a user enters their credentials at the Windows logon screen, LSASS accesses the SAM database.
  2. Exemption Check: LSASS checks whether the user account has the "Password never expires" flag enabled. If this flag is present, the expiration calculation is bypassed.
  3. Age Calculation: If expiration is active, LSASS subtracts the account's "Password Last Set" timestamp from the current system time.
  4. Threshold Comparison: The resulting duration is compared against the configured "Maximum password age" value.

Expiration Triggers and User Action

Windows 10 responds based on the calculated age of the password:

  • Advance Warning: Prior to full expiration, the system displays an interactive notification upon logon informing the user that their password will expire in a specific number of days, offering an immediate option to update it.
  • Mandatory Change: Once the current time exceeds the maximum password age, LSASS marks the account status as expired. Authentication to the desktop environment is halted. The logon screen displays a message stating that the user must change their password before signing in.
  • Validation of the New Password: The user is prompted to input their old password followed by a new one. The new entry is checked against other active local policies (such as minimum password age, password history, and complexity requirements) before the SAM updates the stored hash and resets the "Password Last Set" timestamp.
