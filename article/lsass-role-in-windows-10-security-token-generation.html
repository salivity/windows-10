LSASS Role in Windows 10 Security Token Generation

The Local Security Authority Subsystem Service (LSASS) is a critical Windows 10 process responsible for enforcing security policy, validating user credentials, and issuing security access tokens. When a user logs in, LSASS coordinates with authentication packages to verify identity and assemble user attributes, group memberships, and system privileges. Once verified, LSASS generates the primary security token that defines the user's security context and governs all access control decisions throughout that user's session.

Credential Validation and Identity Lookup

Before a token can be created, LSASS validates the user's submitted credentials. When a user provides authentication data via the Windows Logon GUI (Credential Providers), the data is routed to lsass.exe. LSASS loads the relevant authentication package—such as Kerberos for domain accounts or NTLM/MSV1_0 for local accounts—to verify the credentials against Active Directory or the local Security Account Manager (SAM) database.

Aggregating Security Attributes

Once identity is confirmed, LSASS compiles the complete security profile for the identity. This process involves:

  • Querying the local database or domain controller to retrieve the user's primary Security Identifier (SID).
  • Enumerating all group SIDs to which the user belongs, including nested and domain groups.
  • Identifying specific user rights and privileges assigned to the account and its groups, such as SeShutdownPrivilege or SeDebugPrivilege.
  • Assigning an integrity level (such as Medium for standard users or High for elevated administrative sessions).

Generating the Access Token

With the user attributes gathered, LSASS interfaces with the Windows kernel's Security Reference Monitor (SRM) to formally generate the Security Access Token. LSASS populates the token structure with:

  • The user's SID.
  • Group SIDs.
  • Granted privileges (enabled, disabled, or available).
  • Default Discretionary Access Control Lists (DACL).
  • Primary group and token source information.
  • Session ID and impersonation restrictions.

In Windows 10, when User Account Control (UAC) is active, LSASS creates two tokens for administrative users: a filtered standard user token for daily tasks and a full administrative token reserved for elevated tasks.

Assigning the Token to the User Session

After building the token, LSASS associates it with the initial logon session. LSASS passes this primary access token to userinit.exe, which launches the user's shell (typically explorer.exe). From that point forward, every process spawned by the user inherits a duplicate of this access token. The operating system kernel references this token whenever the user or their processes attempt to open handles to securable objects such as files, registry keys, and processes.
