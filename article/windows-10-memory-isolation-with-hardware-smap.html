Windows 10 Memory Isolation with Hardware SMAP

Supervisor Mode Access Prevention (SMAP) is a hardware-enforced CPU security feature that Windows 10 utilizes to prevent the kernel from executing unauthorized read or write operations on user-space memory pages. By isolating user-mode memory from kernel-mode processes at the hardware level, Windows 10 eliminates entire classes of privilege escalation exploits, ensuring that compromised kernel code cannot inadvertently or maliciously access user data.

The Role of SMAP in Windows 10

In modern operating systems, virtual memory is split between user mode (Ring 3) and kernel mode (Ring 0). Historically, kernel code retained implicit read and write permissions across all user-space memory pages. Attackers frequently exploited this by tricking the kernel into dereferencing user-controlled pointers to execute malicious payloads or hijack control flow.

SMAP, introduced in modern x86-64 processors by Intel and AMD, prevents this behavior by treating user pages as inaccessible by default whenever the CPU is executing in supervisor mode (Ring 0).

Enabling and Initializing SMAP

During the boot phase, Windows 10 detects CPU capabilities by querying the CPUID instruction. If the processor supports SMAP, the Windows kernel initialization routine enables the feature by setting the 21st bit of the Control Register 4 (CR4.SMAP).

Once active, the CPU strictly enforces access restrictions based on the User/Supervisor (U/S) flag located in the page table entries (PTEs):

  • If a page is marked as a user page (U/S = 1), supervisor-mode code cannot read or write to it by default.
  • If a page is marked as a supervisor page (U/S = 0), the kernel retains standard access permissions.

Controlled User-Space Access via STAC and CLAC

Kernel operations frequently require legitimate data exchange with user-space applications, such as copying data buffers during system calls. To facilitate this without disabling global memory isolation, Windows 10 uses explicit instruction pairs to temporarily override SMAP:

  1. Alignment Check (AC) Flag: SMAP enforcement relies on the AC flag within the CPU's EFLAGS register. When CR4.SMAP is active and the AC flag is 0, supervisor-mode access to user pages is prohibited.
  2. STAC (Set AC Flag): Before reading from or writing to a user-mode buffer, the Windows kernel executes the STAC instruction, setting EFLAGS.AC to 1. This temporarily suspends SMAP enforcement for the current thread.
  3. Buffer Validation: The kernel verifies the user-space address using memory manager functions (such as ProbeForRead or ProbeForWrite) and performs the necessary data transfer.
  4. CLAC (Clear AC Flag): Immediately after completing the memory transfer, the kernel executes the CLAC instruction, resetting EFLAGS.AC to 0 and restoring strict hardware-level isolation.

Fault Handling and Exploit Mitigation

If kernel-mode code attempts to access a user-space memory address while the AC flag is cleared, the processor immediately halts the operation and triggers a Page Fault (#PF) exception. The CPU sets the fault's error code to indicate an SMAP violation.

Because the violation occurs inside the kernel, Windows 10 handles this fault as an unhandled kernel exception, triggering a Blue Screen of Death (typically ATTEMPTED_EXECUTE_OF_NOEXECUTE_MEMORY or KMODE_EXCEPTION_NOT_HANDLED). By crashing the operating system rather than permitting the illegal memory read or write, Windows 10 completely neutralizes the exploit vector.
