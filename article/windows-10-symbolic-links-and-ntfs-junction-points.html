Windows 10 Symbolic Links and NTFS Junction Points

Microsoft Windows 10 utilizes the NTFS file system to provide path-redirection mechanisms that allow files and folders to reference alternate locations on storage drives without duplicating data. The two primary methods for achieving this are NTFS Junction Points and Symbolic Links (Symlinks). While both mechanisms rely on NTFS reparse points to transparently route applications and users to a target location, Windows 10 handles them differently regarding network traversal, target types, path formats, and user security permissions.

NTFS Junction Points

Introduced in NTFS 3.0 with Windows 2000, junction points serve as hard-link equivalents for directories.

  • Target Restrictions: Junction points can link only to local directories. They cannot link to individual files or remote network shares (UNC paths).
  • Path Resolution: Junctions use absolute local paths. If the drive letter or path structure of the host volume changes, the junction point breaks.
  • Processing: The local operating system's NTFS file system driver resolves junction points entirely on the host machine.
  • Permissions: In Windows 10, any standard user can create a junction point using the command-line utility mklink /J <Link> <Target> without needing administrative elevation, provided the user has write access to the directory where the link is created.

Symbolic Links (Symlinks)

Introduced in Windows Vista and refined in Windows 10, symbolic links are advanced file system shortcuts designed to mirror Unix-style soft links.

  • Target Versatility: Symlinks can target both directories (created with mklink /D) and individual files (created with standard mklink).
  • Path Flexibility: Symlinks support both absolute paths and relative paths. A relative link remains functional if the parent folder hierarchy is moved together.
  • Remote Redirection: Symlinks support network targets, allowing references to UNC paths (e.g., \\Server\Share).
  • Client-Side Resolution: When a symlink points to a remote network path, the path resolution occurs on the client machine rather than the file server, ensuring remote security boundaries remain intact.
  • Permissions and Developer Mode: By default, creating symbolic links requires elevated administrative privileges or the SeCreateSymbolicLinkPrivilege user right to mitigate security risks such as directory traversal attacks. However, Windows 10 allows non-administrative users to create symlinks if Developer Mode is enabled under the system's "For developers" settings.

File System Mechanics and Reparse Points

Windows 10 manages both structures through NTFS reparse points. A reparse point contains user-defined data and a specific tag identifying the link type:

  • Junction Points: Tagged as IO_REPARSE_TAG_MOUNT_POINT.
  • Symbolic Links: Tagged as IO_REPARSE_TAG_SYMLINK.

When an application opens a path containing a reparse point, the Windows I/O manager intercepts the request, recognizes the reparse tag, and restarts the path lookup using the target data stored inside the tag. Most user-mode applications interact with junctions and symlinks transparently, treating them as normal directories or files.

Deleting a junction point or symbolic link in Windows 10 removes only the reparse point reference; the underlying target data remains intact. However, modifying or deleting the contents displayed inside a linked directory will alter or delete the files located at the target destination.
