Windows 10 Bluetooth Pairing and Audio Codecs

The Microsoft Windows 10 operating system manages wireless audio connections through a standardized Bluetooth software stack that handles both device pairing and audio profile configuration. When connecting to wireless headphones or speakers, Windows 10 establishes a secure hardware bond using the Bluetooth core architecture, establishes communication via audio-specific profiles, and negotiates the optimal audio codec using the Audio/Video Distribution Transport Protocol (AVDTP) to balance latency, bandwidth, and audio fidelity.

The Bluetooth Pairing Process

Bluetooth pairing in Windows 10 is managed by the Windows Bluetooth subsystem, primarily driven by the Bluetooth Support Service (bthserv) and the system's radio drivers. The pairing sequence follows standard Bluetooth Core Specifications:

  1. Discovery and Inquiry: When the user opens the Windows 10 Bluetooth settings or uses Swift Pair, the OS instructs the host Bluetooth adapter to scan for advertisement packets broadcast by nearby devices in pairing mode.
  2. Authentication and Key Exchange: Windows 10 primarily utilizes Secure Simple Pairing (SSP) for modern Bluetooth Classic devices, or Secure Connections for Bluetooth Low Energy (LE). Depending on the device capabilities, the OS negotiates one of four association models:
    • Just Works: Used when the audio device lacks a display or input interface. The authentication occurs without user confirmation, though encryption keys are still generated.
    • Numeric Comparison: Used if both endpoints can display a 6-digit code.
    • Passkey Entry: Used if one device requires a PIN entered on the host.
  3. Link Key Generation and Bonding: Upon successful authentication, Windows 10 and the audio device generate a shared Link Key (or Long-Term Key for LE). Windows stores this key securely in the system registry, allowing the OS to automatically authenticate and reconnect to the device in subsequent sessions without user intervention.

Audio Profiles and Role Assignment

Once paired, Windows 10 queries the device’s Service Discovery Protocol (SDP) records to identify supported profiles. For audio hardware, Windows initializes two distinct profiles:

  • Advanced Audio Distribution Profile (A2DP): Configures the PC as an Audio Source (SRC) and the receiving device as an Audio Sink (SNK). This profile is used for unidirectional, high-quality stereo media playback.
  • Hands-Free Profile (HFP) or Headset Profile (HSP): Configures bidirectional, low-bandwidth audio for voice communications (such as VoIP calls or teleconferencing) alongside microphone input.

Windows 10 routes system sound through the A2DP profile by default and dynamically switches to or enables HFP when an application requests microphone access.

Audio Codec Negotiation

Codec negotiation takes place within the A2DP framework via the Audio/Video Distribution Transport Protocol (AVDTP). The process occurs in sequential phases:

  1. Stream Endpoint Discovery: Windows 10 sends an AVDTP_DISCOVER request to the sink device to identify all available Stream Endpoints (SEPs) and their media types.
  2. Capability Query: Windows queries each endpoint with AVDTP_GET_CAPABILITIES. The sink device responds with its supported codecs and parameters, such as sampling rates (e.g., 44.1 kHz, 48 kHz), channel modes (Stereo, Joint Stereo), and bitpool ranges.
  3. Codec Selection: Windows 10 evaluates the sink's supported codecs against its own internal priority list:
    • SBC (Subband Codec): The mandatory baseline codec for all A2DP devices. Windows supports standard SBC configurations with typical bitrates up to 328 kbps.
    • Qualcomm aptX: Natively supported in Windows 10 for devices that include aptX licensing capabilities, providing fixed-bitrate, lower-latency compression.
    • AAC (Advanced Audio Coding): Added natively to Windows 10 in later feature updates (Build 21370 and onward, carried forward into 21H2), offering higher efficiency compression.
  4. Configuration Lock: The OS selects the highest-priority codec supported by both the host adapter/software stack and the receiving device. Windows then transmits an AVDTP_SET_CONFIGURATION command containing the chosen codec, sample rate, and bitpool settings. Once acknowledged by the sink, the stream endpoint is opened via AVDTP_OPEN, and the Windows Audio Engine begins routing PCM audio through the selected codec encoder for transmission over the radio link.
