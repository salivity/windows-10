How Windows 10 Calculates App Battery Usage

Windows 10 tracks and displays per-app battery consumption by continuously monitoring hardware component activity, logging resource consumption through internal telemetry services, and attributing the estimated power draw to specific software processes. This article explains the underlying mechanisms Windows 10 uses to measure energy expenditure, categorize foreground versus background activity, and present clear battery usage statistics within the operating system's settings.

The Energy Estimation Engine (E3)

At the core of Windows 10 battery tracking is the Energy Estimation Engine (E3). Because typical consumer device hardware lacks dedicated physical power meters on individual components (like per-process power sensors on the CPU or network card), Windows uses a software-based estimation model.

The E3 service relies on pre-calibrated energy profiles specific to the device's hardware configuration. It assigns mathematical energy coefficients to various hardware states, measuring power across key components:

  • CPU: Processor time, clock frequency states (P-states), and core execution cycles.
  • GPU: Graphics rendering, video decoding, and compute engine utilization.
  • Display: Screen brightness levels and display state changes.
  • Network: Wi-Fi and cellular modem active transmit/receive states versus low-power idle states.
  • Disk: Read and write input/output operations.

Data Collection via System Resource Usage Monitor (SRUM)

The actual usage data is captured by the System Resource Usage Monitor (SRUM). Running persistently as a background service, SRUM records resource metrics tied to specific Process IDs (PIDs) and application user accounts.

Every few seconds, SRUM queries hardware performance counters and driver logs to measure how long each process used specific hardware states. This data is buffered in memory and periodically committed to an Extensible Storage Engine (ESE) database located on the system drive (C:\Windows\System32\sru\SRUDB.dat). By maintaining this database, Windows 10 preserves usage logs even across system restarts and sleep cycles.

Distinguishing Foreground vs. Background Usage

Windows 10 classifies power usage into two distinct categories:

  1. In Use (Foreground): Power drawn while the application window is actively focused, visible, and being interacted with by the user. Display and GPU consumption are primarily attributed to foreground applications.
  2. Background: Power consumed when the application is minimized, running without an active user interface, or performing maintenance tasks via background triggers (such as push notifications, media playback, or syncing).

The Desktop Window Manager (DWM) and process scheduler provide the context required to segment these measurements, allowing Windows to show the user whether an app is draining power during active use or passively while hidden.

Calculating Percentage Breakdown

To display the data in Settings > System > Battery > Battery usage per app, Windows aggregates the metrics over selected time windows (typically the last 24 hours or the last 7 days):

  1. Sum Total Energy: The system calculates the estimated total milliwatt-hours (mWh) drawn by all software components and hardware peripherals during the measured period.
  2. Per-Process Attribution: Each application's cumulative resource consumption is multiplied by the corresponding hardware power coefficients to derive its individual estimated energy total.
  3. Proportional Scaling: The application's individual power draw is divided by the total software energy consumed, producing the final percentage shown to the user.

Processes that register negligible activity (typically under 1% of the total usage) are often omitted from the display or aggregated into overall system metrics to keep the interface simple and actionable.
