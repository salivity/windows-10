How Windows 10 NCSI Detects Internet Access

The Network Connectivity Status Indicator (NCSI) is a core Windows 10 operating system component responsible for determining whether a device has local network connectivity, full internet access, or is trapped behind a captive portal. This article explores how NCSI performs active and passive network probes, updates the system tray connection status, and communicates network availability to both core operating system services and third-party applications.

NCSI operates within the Network Awareness subsystem to evaluate connectivity states as soon as a network interface connects to a router or access point. Its primary objective is to verify that the local connection can reach the broader internet, preventing applications from attempting external connections when only local subnet communication is possible.

To determine connectivity, NCSI uses two primary mechanisms: active probing and passive monitoring.

Active Probing

Active probing is initiated automatically whenever an interface connects to a new network or when changes in IP configuration occur. The process follows a structured sequence:

  1. DNS Resolution: NCSI issues a DNS request to resolve a dedicated Microsoft domain, typically www.msftconnecttest.com (or dns.msftncsi.com in older builds). If this query fails or returns an unexpected address, NCSI flags the connection as lacking internet access.
  2. HTTP/HTTPS Request: Upon successful resolution, NCSI sends an HTTP GET request to download a specific plain text file, such as connecttest.txt (which contains the text "Microsoft Connect Test").
  3. Response Validation: NCSI reads the returned payload. If the server returns an HTTP 200 OK status along with the exact expected string, Windows confirms functional, direct internet access.
  4. Captive Portal Identification: If the HTTP request returns a redirect (HTTP 302) or unexpected HTML markup, NCSI recognizes that a captive portal—such as a hotel or airport login page—is intercepting traffic. It then triggers an action center prompt alerting the user to log in.

Passive Probing

To minimize bandwidth and avoid sending continuous active requests, NCSI shifts to passive monitoring during normal system operation. It monitors the metadata of active network traffic generated by user applications, such as TCP handshake successes and hop counts. If regular TCP traffic continues without failure, NCSI maintains the "Internet access" state without generating synthetic probes. If packet transmission fails consistently, it triggers a new active probe to re-verify the connection.

Impact on Windows Services and Applications

The status determined by NCSI dictates the behavior of the operating system:

  • Taskbar Status: It controls the network icon in the system tray, switching between the connected monitor/Wi-Fi symbol, the captive portal prompt, and the disconnected "globe" icon.
  • API Availability: NCSI exposes the connection state through the Network List Manager (NLM) API. Applications such as Microsoft Outlook, OneDrive, and Windows Update query this API to decide whether to attempt synchronization or defer operations until genuine internet access is restored.
