Windows 10 Variable Refresh Rate Implementation

Variable Refresh Rate (VRR) allows a monitor to dynamically adjust its refresh rate to match the frame delivery cadence of the graphics processing unit (GPU), eliminating screen tearing and reducing input latency. In the Windows 10 May 2019 Update (Version 1903), Microsoft implemented an operating system-level VRR framework within the graphics architecture to bridge the gap between legacy display pipelines and modern adaptive sync hardware. This article explains how the Windows 10 display stack, the Desktop Window Manager (DWM), and the Windows Display Driver Model (WDDM) coordinate to enable seamless VRR across both native full-screen and borderless windowed environments.

The Role of the Windows Display Driver Model (WDDM)

Windows 10 manages hardware communication through the Windows Display Driver Model. Starting with WDDM 2.6, Microsoft added core support for variable refresh rate handling at the kernel level.

Under older WDDM versions, dynamic refresh rate logic was handled almost exclusively by proprietary graphics driver hooks (such as NVIDIA G-Sync or AMD FreeSync) interfacing directly with the display. With WDDM 2.6 and later, the OS recognizes VRR as a fundamental display capability. The driver queries the display's Extended Display Identification Data (EDID) or DisplayID to identify the supported frequency range (e.g., 48 Hz to 144 Hz) and exposes these timing capabilities directly to the Windows graphics kernel (Dxgkrnl).

Bypassing Desktop Window Manager (DWM) Constraints

Historically, exclusive full-screen mode was required to synchronize the display panel directly with the GPU swap chain. In standard windowed or borderless windowed modes, every rendered frame passes through the Desktop Window Manager (DWM). The DWM composes all desktop elements at a fixed refresh rate synchronized to the primary monitor’s vertical blanking interval (VBLANK), which traditionally broke variable refresh rate mechanisms.

Windows 10 implements VRR by altering how DWM handles swap chain presentation:

  • Direct Flip and Independent Flip (iFlip): When a game runs in borderless windowed mode and covers the viewport, the DWM disengages standard desktop composition via Independent Flip. This allows the application swap chain to communicate directly with the display scan-out hardware.
  • Tear-Free Frame Pacing: When the OS-level VRR feature is active, Windows instructs the DWM composition engine to suspend fixed-interval pacing for the focused surface. If the frame rate drops within the monitor’s VRR range, the display controller delays the vertical sync pulse until the GPU completes rendering the new frame.

The OS-Level VRR Toggle and Legacy Compatibility

Windows 10 includes a dedicated "Variable refresh rate" toggle located under Settings > System > Display > Graphics settings.

This system-level toggle does not replace NVIDIA G-Sync or AMD FreeSync control panels; instead, it acts as an operational bridge for legacy application programming interfaces (APIs). DirectX 12 natively supports explicit swap chain flags for tearing and variable refresh rates (such as DXGI_SWAP_CHAIN_FLAG_ALLOW_TEARING). However, older DirectX 11 titles were not programmed with these presentation flags.

When the Windows 10 VRR setting is enabled:

  1. The OS intercepts legacy presentation requests from DirectX 11 applications.
  2. It translates standard flip-model presentations into modern, VRR-compatible presentation models.
  3. It informs the underlying graphics driver that the application is permitted to modulate panel scan-out times, even if the application did not natively declare VRR support.

System Requirements for Implementation

For the Windows 10 VRR pipeline to function, three baseline criteria must be met:

  • OS Version: Windows 10 Version 1903 (Build 18362) or higher.
  • Driver Architecture: A GPU driver supporting WDDM 2.6 or newer.
  • Display Support: A display and connection interface (HDMI 2.1 Variable Refresh Rate, DisplayPort Adaptive-Sync, G-Sync, or FreeSync) with active adaptive sync capabilities enabled at the firmware level.
