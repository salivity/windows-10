Windows 10 Subnet Mask and Gateway Configuration

This article explains how the Microsoft Windows 10 operating system handles the configuration of local subnet masks and default gateways. It details the underlying network mechanisms—both dynamic assignment through DHCP and manual static assignment—and covers how the Windows TCP/IP stack applies these settings to separate local network traffic from outbound internet traffic.

Dynamic Configuration (DHCP and APIPA)

By default, Windows 10 automatically obtains network parameters using the Dynamic Host Configuration Protocol (DHCP). When a network adapter connects to a network, the Windows DHCP client service broadcasts a discovery packet. A local DHCP server (typically a home router or corporate domain server) responds with an IP configuration offer that includes:

  • Subnet Mask: Defines the boundary between the network identifier and the host identifier, typically 255.255.255.0 (/24) for standard local networks.
  • Default Gateway: The IP address of the router interface on the local subnet that routes packets outside the local network.

If a DHCP server cannot be reached, Windows 10 falls back to Automatic Private IP Addressing (APIPA). In this state, Windows assigns an IP address in the 169.254.0.1 to 169.254.255.254 range with a fixed Class B subnet mask of 255.255.0.0. In an APIPA state, no default gateway is assigned, meaning traffic remains strictly confined to the local link.

Manual Configuration (Static Assignment)

Windows 10 allows users and administrators to bypass automatic assignment and statically assign a subnet mask and default gateway through several interfaces:

  • Windows Settings: Under Settings > Network & Internet > Status, users can select Properties on an active connection, choose Edit under IP settings, switch from Automatic (DHCP) to Manual, and specify the IP address, subnet prefix length (CIDR notation), and default gateway.
  • Control Panel (ncpa.cpl): In the classic Network Connections panel, open the adapter's Properties, select Internet Protocol Version 4 (TCP/IPv4), click Properties, and explicitly enter the Subnet Mask in dotted-decimal format and the Default Gateway address.
  • PowerShell / Command Prompt: Administrators can use PowerShell's New-NetIPAddress cmdlet or the legacy netsh utility:
    • PowerShell: New-NetIPAddress -InterfaceAlias "Ethernet" -IPAddress 192.168.1.50 -PrefixLength 24 -DefaultGateway 192.168.1.1
    • Command Prompt: netsh interface ip set address name="Ethernet" static 192.168.1.50 255.255.255.0 192.168.1.1

Internal Handling in the TCP/IP Stack

Once configured, Windows 10 writes the values to the Windows Registry under HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\Tcpip\Parameters\Interfaces\{Adapter-GUID}.

The TCP/IP stack (tcpip.sys) uses the subnet mask to execute a bitwise AND operation on outgoing packets. If the destination IP shares the same network prefix as the host, Windows determines the destination is on the local link and resolves the destination hardware address directly via the Address Resolution Protocol (ARP).

If the destination IP does not match the local subnet, the stack references its internal routing table (viewable via the route print command). The default gateway is placed in the routing table as the next-hop address for the default route (0.0.0.0 with netmask 0.0.0.0), prompting Windows to encapsulate the packet with the MAC address of the default gateway for external routing.
