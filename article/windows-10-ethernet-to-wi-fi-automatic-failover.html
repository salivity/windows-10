Windows 10 Ethernet to Wi-Fi Automatic Failover

Windows 10 handles automatic network failover between Ethernet and Wi-Fi using an internal routing metric system and real-time connection monitoring. By default, the operating system assigns priority based on connection speed and connection state, routing all network traffic through the fastest, most stable link—typically wired Ethernet. If that primary connection disconnects or loses internet access, Windows instantly redirects active traffic to the secondary Wi-Fi adapter without requiring user intervention.

The Role of Interface Metrics

Windows 10 relies on a TCP/IP routing feature called Interface Metric to determine which network adapter takes precedence when multiple connections are active. Every network route in Windows is assigned a metric value, which acts as a cost; the operating system always routes traffic through the adapter with the lowest metric.

By default, the "Automatic Metric" feature is enabled on all network adapters. Windows assigns these metrics dynamically based on the reported link speed of the adapter:

  • High-Speed Wired Ethernet (1 Gbps or higher): Assigned a low metric (typically 10 to 25).
  • Fast Ethernet (100 Mbps): Assigned a metric around 20 to 25.
  • Standard Wi-Fi (802.11ac/ax, variable signal): Assigned a higher metric (typically 35 to 50 or higher, depending on link negotiation).

Because the Ethernet adapter negotiates a higher throughput and lower latency, Windows assigns it a lower numerical metric than the Wi-Fi adapter, establishing Ethernet as the primary gateway for all outbound traffic.

Network Connectivity Status Indicator (NCSI)

Windows 10 does not only look at physical link states (such as an unplugged cable); it continuously verifies active internet reachability using the Network Connectivity Status Indicator (NCSI).

  1. Active Probing: NCSI periodically sends a DNS request to resolve a specific Microsoft domain (such as dns.msftncsi.com) and attempts to download a lightweight text file (such as http://www.msftncsi.com/ncsi.txt).
  2. Passive Monitoring: The system tracks TCP connection activity and packet retries to detect degraded network health.

If Ethernet physical link is lost (unplugged cable) or NCSI determines the Ethernet path has no internet route, Windows modifies the routing table. The route associated with that adapter is either removed or marked unreachable.

How the Automatic Failover Occurs

  1. Simultaneous Association: When both Ethernet and Wi-Fi are turned on, both adapters connect to their respective networks and obtain IP configurations (via DHCP or static assignment).
  2. Routing Table Hierarchy: Windows builds the routing table with default gateways for both adapters, placing the lower-metric Ethernet route at the top.
  3. Trigger Event: If the Ethernet cable is unplugged or the local wired gateway goes down:
    • The media state changes to disconnected, or NCSI flags the route as unusable.
    • Windows immediately withdraws the Ethernet default gateway from active route selection.
  4. Instant Switch: The Wi-Fi adapter’s gateway becomes the route with the lowest active metric. Subsequent TCP/IP packets are immediately routed through the Wi-Fi interface.
  5. Failback: Once the Ethernet cable is reconnected and internet access is verified via NCSI, its low metric route is reinserted at the top of the routing table, automatically shifting traffic back to Ethernet.

Configuring or Overriding Automatic Failover

If Windows 10 does not prioritize Ethernet over Wi-Fi automatically, you can manually define the adapter priorities:

  1. Press Win + R, type ncpa.cpl, and press Enter to open Network Connections.
  2. Right-click your Ethernet adapter and select Properties.
  3. Select Internet Protocol Version 4 (TCP/IPv4) and click Properties.
  4. Click Advanced.
  5. At the bottom of the IP Settings tab, uncheck Automatic metric.
  6. Enter 10 in the Interface metric field and click OK.
  7. Repeat the process for your Wi-Fi adapter, but set its Interface metric to 20 or higher.

Assigning a lower number to the Ethernet adapter guarantees that Windows 10 uses it as the primary interface whenever connected, seamlessly dropping back to Wi-Fi only when the wired route is offline.
