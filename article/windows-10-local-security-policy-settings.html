Windows 10 Local Security Policy Settings

This guide outlines the critical security configurations that can be managed through the Local Security Policy interface (secpol.msc) in the Windows 10 operating system. It details the primary policy categories available to administrators, explaining how each section contributes to system hardening, user access restriction, and operational monitoring.

Account Policies

Account Policies govern the authentication mechanisms and credential requirements for local user accounts.

  • Password Policy: Enforces rules for user passwords, including minimum password length, maximum and minimum password age, password history to prevent reuse, and complexity requirements (requiring uppercase letters, lowercase letters, numbers, and symbols). It also includes reversible encryption settings.
  • Account Lockout Policy: Protects the system against brute-force attacks by specifying an account lockout threshold (the number of failed logon attempts permitted), the account lockout duration (how long the account remains locked), and the reset timer for the failed logon counter.

Local Policies

Local Policies control core system privileges, event logging, and fundamental operating system security behaviors.

  • Audit Policy: Determines which security events are recorded in the Windows Security Event Log. Administrators can configure tracking for success, failure, or both across events such as account logon, account management, directory service access, object access, policy changes, privilege use, process tracking, and system events.
  • User Rights Assignment: Grants specific rights and permissions to users and groups. Key settings include:
    • Allowing or denying logons via Remote Desktop Services.
    • Accessing the computer from the network.
    • Shutting down or restarting the system.
    • Taking ownership of files or other objects.
    • Backing up and restoring files and directories.
    • Debugging programs and loading device drivers.
  • Security Options: Contains granular settings controlling OS-level protections, such as:
    • User Account Control (UAC): Configures prompt behaviors for administrators and standard users, credential virtualization, and installer detection.
    • Interactive Logon: Configures warning banners (legal notices), CTRL+ALT+DEL requirements, machine lock thresholds, and behavior when smart cards are removed.
    • Network Security and Access: Regulates LAN Manager authentication levels, anonymous access restrictions to shares and named pipes, and SMB signing requirements.
    • Device Restrictions: Restricts the formatting and ejection of removable media or blocks CD-ROM/floppy access to locally logged-on users.

Windows Defender Firewall with Advanced Security

This node manages host-based network security rules locally.

  • Inbound Rules: Restricts incoming traffic based on port, protocol, IP address, or executable.
  • Outbound Rules: Restricts outbound network communication initiated by local software.
  • Connection Security Rules: Enforces IPsec authentication and encryption for end-to-end communication between network hosts.

Network List Manager Policies

Administrators can use this policy area to define how the system recognizes and treats different network connections (e.g., Domain, Private, or Public), dictating whether users can change network locations or configure permissions for unauthenticated networks.

Public Key Policies

Controls how public key cryptography and digital certificates function on the local machine:

  • Encrypting File System (EFS): Specifies data recovery agents and enforces encryption algorithms.
  • Certificate Path Validation: Enforces store rules, revocation checking, and root authority trust settings.

Software Restriction Policies and AppLocker

These policies control which software can execute on the operating system to prevent unauthorized programs and malware.

  • Software Restriction Policies: Employs basic hash, certificate, path, and internet zone rules to permit or deny application execution.
  • AppLocker (Application Control Policies): Provides modern application whitelisting and blacklisting. It allows administrators to create rules based on file publisher, hash, or path for:
    • Executable files (.exe, .com).
    • Windows Installer files (.msi, .msp).
    • Scripts (.ps1, .bat, .cmd, .vbs, .js).
    • Packaged apps and app installers (.appx).

Advanced Audit Policy Configuration

Provides a granular alternative to the basic Audit Policy, dividing standard audit categories into detailed subcategories. This enables administrators to audit specific activities—such as File System access, Registry modification, DPAPI activity, and RPC events—without generating excessive log volume for unrelated actions.
