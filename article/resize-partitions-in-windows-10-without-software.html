Resize Partitions in Windows 10 Without Software

Microsoft Windows 10 provides native support for dynamic partition resizing directly through its built-in utilities, Disk Management and the DiskPart command-line tool. Without relying on third-party software, users can adjust drive capacities by shrinking or extending existing NTFS or ReFS volumes on the fly. This article explains the underlying mechanisms that enable live partition adjustments in Windows 10, the built-in utilities used to perform them, and the fundamental rules governing the process.

The Underlying Technology

Windows 10 handles dynamic partition resizing through native file system capabilities built into NTFS and ReFS. When dynamic changes occur, the operating system works directly with the Virtual Disk Service (VDS) and the storage stack. Because modern Windows file systems support online operations, volume resizing does not require system reboots or offline maintenance modes, provided the volume meets specific structural criteria.

Primary Built-in Tools

Windows 10 includes two native utilities to resize volumes:

  1. Disk Management (GUI): A graphical Microsoft Management Console (MMC) snap-in accessible by pressing Win + X and selecting "Disk Management." It provides an interactive visual map of all physical disks, partitions, and unallocated spaces.
  2. DiskPart (CLI): A powerful command-line disk partitioning utility run from an elevated Command Prompt or PowerShell. It provides scriptable, granular control over disks, partitions, and volumes.

How Shrinking a Volume Works

Shrinking reduces the space allocated to an existing partition, turning the freed space into unallocated space.

  • File Relocation: When a shrink operation is initiated, the operating system analyzes the volume's cluster allocation. It determines the maximum boundary to which the partition can be reduced based on the location of files.
  • Immovable Files Limitation: Windows cannot automatically relocate certain system files—such as the paging file, hibernation files (hiberfil.sys), or Volume Shadow Copy checkpoints. The maximum amount a volume can shrink is dictated by the physical location of the last unmovable file on the disk cluster map.
  • Execution: In Disk Management, right-clicking a volume and selecting Shrink Volume prompts Windows to query the available space, allowing the user to specify the reduction amount in megabytes. In DiskPart, this is achieved using the shrink desired=[size] command.

How Extending a Volume Works

Extending allows a partition to grow by consuming adjacent empty space.

  • The Contiguity Requirement: Windows 10 requires that unallocated space be directly adjacent (contiguous) to the right side of the partition you wish to expand on a Basic disk. If a recovery partition, another data partition, or system reserved data lies between the target partition and the unallocated space, the "Extend Volume" option will be grayed out.
  • Execution: Once contiguous unallocated space is available to the right, users can right-click the target volume in Disk Management and select Extend Volume. In DiskPart, selecting the volume and entering the extend command instantly appends the available space to the file system.

Key Operational Rules and Limitations

  • Supported File Systems: Online shrinking and extending are supported on NTFS and ReFS. Partitions formatted with FAT32 or exFAT cannot be resized using Windows 10 native tools.
  • Dynamic Disks vs. Basic Disks: On standard Basic disks, extension is strictly limited to contiguous space on the same drive. If the disk is converted to a Dynamic disk, Windows allows the creation of spanned or striped volumes across non-contiguous blocks or separate physical drives, though this setup cannot host bootable system volumes.
