How Windows 10 Allocates CPU Thread Affinity

In Microsoft Windows 10, the operating system allocates CPU processor affinity to active threads through a sophisticated kernel dispatcher designed to balance thread priority, system cache locality, and modern multi-core processor architectures. By default, the Windows scheduler evaluates hardware topologies—including Non-Uniform Memory Access (NUMA) nodes, Simultaneous Multithreading (SMT), and heterogeneous core types—to dynamically assign threads to the most efficient logical processor. While the operating system prioritizes throughput and low latency via "soft affinity," it also respects application-defined constraints known as "hard affinity."

Soft Affinity vs. Hard Affinity

The Windows 10 scheduler operates primarily on the concept of soft affinity. Under soft affinity, the operating system attempts to keep a thread running on the same logical processor or the same processor cache domain (L1/L2/L3) where it last executed. This approach reduces cache misses and minimizes the performance penalties associated with transferring thread context and cache lines between different physical cores. However, if that processor is busy and another suitable core is idle, the scheduler migrates the thread to avoid execution delays.

In contrast, hard affinity occurs when an application developer or user explicitly restricts a thread or entire process to a defined subset of logical processors. Developers use Windows API functions such as SetProcessAffinityMask or SetThreadAffinityMask, while users can set affinity manually via Task Manager. When hard affinity is applied, the Windows kernel strictly enforces the mask: the thread will execute only on the designated processors, even if those cores are at 100% utilization while other system cores sit idle.

The Ideal Processor Concept

To streamline assignment without rigid restrictions, Windows 10 assigns an Ideal Processor to every active thread.

  • When a thread is created, the system assigns a preferred processor based on a round-robin distribution within the process’s assigned NUMA node.
  • Developers can also suggest an optimal core using the SetThreadIdealProcessor or SetThreadIdealProcessorEx APIs.
  • When a thread transitions from a waiting state to a ready state, the scheduler first checks whether the ideal processor is available. If it is idle, execution begins there. If it is occupied, the scheduler checks sibling cores that share the same cache before finally looking at other cores within the same NUMA node.

Topology and NUMA Awareness

Windows 10 is deeply aware of physical CPU architecture, which guides affinity decisions:

  • Processor Groups: For systems with more than 64 logical processors, Windows 10 organizes processors into distinct Processor Groups. Threads are typically assigned to execute within a single group to maintain affinity limits, though modern multi-group APIs allow cross-group scheduling.
  • NUMA Nodes: In multi-socket or multi-die configurations, memory access is fastest when a thread accesses local RAM. The scheduler binds threads to cores within the specific NUMA node where the thread’s working set memory is allocated.
  • SMT/Hyper-Threading: The scheduler recognizes logical cores that share physical execution units. To maximize performance, Windows prioritizes scheduling independent threads on separate physical cores before assigning threads to simultaneous logical threads on the same core.

Heterogeneous and Energy-Aware Scheduling

In modern releases of Windows 10 running on hybrid processors (such as architectures combining Performance cores and Efficient cores), affinity allocation is further refined through Quality of Service (QoS) levels and hardware feedback mechanisms. The operating system monitors the execution profile of a thread: foreground, high-priority tasks are steered toward high-performance cores, while background, low-priority, or parked tasks are assigned to energy-efficient cores. This dynamic routing ensures optimal responsiveness without requiring manual affinity adjustments from the user.
