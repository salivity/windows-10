Windows 10 Proxy Setup Using PAC Script URLs

This article explains how the Microsoft Windows 10 operating system configures network proxy settings using Proxy Auto-Configuration (PAC) script URLs. It covers the technical role of PAC scripts in dynamic traffic routing, step-by-step methods to apply a PAC URL via the Windows Settings app, legacy Internet Properties, Group Policy, and the Windows Registry, as well as how the underlying Windows network stack downloads and executes these scripts.

What is a PAC Script?

A Proxy Auto-Configuration (PAC) file is a JavaScript file that defines how web browsers and other network clients automatically choose the appropriate proxy server for fetching a given URL. The file contains a core JavaScript function named FindProxyForURL(url, host). When configured, Windows 10 queries this function before initiating an outbound connection, dynamically determining whether to send traffic through a specific proxy server or establish a direct connection.

How Windows 10 Configures PAC URLs

Windows 10 exposes several mechanisms for users and system administrators to define the PAC script URL (often referred to as an "Automatic configuration script" or "Setup script").

1. Via the Modern Windows Settings App

This is the standard interface for individual users:

  1. Open Settings (press Win + I).
  2. Navigate to Network & Internet > Proxy.
  3. Under the Automatic proxy setup section, toggle the Use setup script switch to On.
  4. In the Script address field, enter the full URL of the .pac file (e.g., http://proxy.corp.example.com/accelerated.pac).
  5. Click Save.

2. Via Legacy Internet Properties (inetcpl.cpl)

Windows 10 maintains backward compatibility with legacy WinINet settings:

  1. Press Win + R, type inetcpl.cpl, and press Enter.
  2. Switch to the Connections tab and click the LAN settings button.
  3. Check the box labeled Use automatic configuration script.
  4. Enter the PAC file URL in the Address text box.
  5. Click OK, then click Apply.

3. Via the Windows Registry

Both modern Settings and legacy Internet Properties write to the Windows Registry. Administrators can set this directly via scripts or command-line tools:

  • Registry Path: HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Internet Settings
  • Value Name: AutoConfigURL
  • Type: REG_SZ (String)
  • Value Data: The PAC script URL (e.g., http://192.168.1.10/wpad.dat)

Setting this value automatically activates the "Use setup script" toggle in the operating system.

4. Via Group Policy (Active Directory / Local GPO)

For enterprise-wide management across multiple Windows 10 machines:

  1. Open the Local Group Policy Editor (gpedit.msc) or Group Policy Management Console.
  2. Navigate to: User Configuration > Administrative Templates > Windows Components > Internet Explorer.
  3. Locate and enable Disable changing Automatic Configuration settings to lock the setting against user modification, or deploy the configuration using Group Policy Preferences under: User Configuration > Preferences > Control Panel Settings > Internet Settings.
  4. Define the PAC file URL inside the automatic configuration dialog.

How Windows 10 Processes the PAC Script at Runtime

Once the PAC URL is saved, the Windows 10 network architecture handles execution using the following process:

  1. Fetching the Script: Windows network APIs (WinINet and WinHTTP) make an HTTP or HTTPS request to retrieve the .pac file from the specified URL into local memory or temporary cache.
  2. Execution via Script Engine: Windows utilizes an isolated, out-of-process scripting host (typically executing through pacjscript.dll) to evaluate the JavaScript function for each destination URL.
  3. Caching and Routing: To reduce latency, Windows caches resolved proxy routes for repeatedly accessed domains. If the destination matches proxy rules in the script, the traffic is redirected to the designated proxy IP and port; otherwise, it connects directly (DIRECT).
  4. Fallback Handling: If the PAC script URL is unreachable or contains syntax errors, Windows falls back to direct network communication or standard failover policies configured within the operating system.
