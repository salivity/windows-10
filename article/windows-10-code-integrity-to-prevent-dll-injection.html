Windows 10 Code Integrity to Prevent DLL Injection

Dynamic-link library (DLL) injection is a prevalent attack technique where malicious code is forced into the address space of a running process to execute under its privileges. The Microsoft Windows 10 operating system counters this threat using robust Code Integrity (CI) policies, primarily implemented through Windows Defender Application Control (WDAC) and Code Integrity Guard (CIG). By shifting security from reactive antivirus detection to proactive signature enforcement, Windows 10 restricts which modules are permitted to load, effectively nullifying traditional and advanced DLL injection vectors.

The Mechanism of DLL Injection

In a standard DLL injection attack, an adversary writes code to a target process's memory space and forces it to execute LoadLibrary or an equivalent API call. If the target process runs with elevated privileges or is considered trusted by security monitoring tools, the injected DLL inherits those privileges while remaining disguised within the legitimate process memory.

Code Integrity Guard (CIG)

Code Integrity Guard is an exploit mitigation feature designed to prevent arbitrary DLL loading in user-mode processes. When CIG is enabled for an application:

  • Signature Enforcement: The Windows kernel validates the cryptographic signature of any dynamic library before mapping it into the target process's virtual memory space.
  • Strict Trust Chains: CIG requires the DLL to be signed by a trusted authority—such as Microsoft, the Windows Hardware Quality Labs (WHQL), or the Microsoft Store—depending on the specific policy applied.
  • Execution Prevention: If an attacker attempts to inject an unsigned, self-signed, or untrusted third-party DLL, the kernel-level code integrity engine rejects the image load request, causing the injection attempt to fail immediately.

Developers and administrators can enforce CIG on specific executables using the SetProcessMitigationPolicy API with the ProcessSignaturePolicy flag or configure it across environments via Group Policy.

Windows Defender Application Control (WDAC)

While CIG operates at the process level, Windows Defender Application Control enforces code integrity across the entire operating system. WDAC policies are compiled into binary format and evaluated by the kernel (CI.dll):

  • System-Wide Restriction: WDAC creates an explicit whitelist defining which DLLs and executables can run based on file hashes, paths, or publisher certificates.
  • Kernel-Enforced Isolation: Because the rules are evaluated within the kernel during the file-mapping phase, an untrusted DLL cannot be loaded by any process on the system, regardless of user privileges or injection mechanisms used.
  • Elimination of Bypass Techniques: Attackers frequently drop malicious DLLs to disk and load them via reflective injection or standard execution calls. WDAC blocks the execution of these binaries before memory allocation occurs.

Virtualization-Based Security (VBS) and HVCI

To prevent attackers with administrative or kernel-level access from tampering with Code Integrity policies, Windows 10 leverages Virtualization-Based Security (VBS) and Hypervisor-Protected Code Integrity (HVCI).

HVCI runs the Code Integrity service inside an isolated virtual container managed by the Hyper-V hypervisor. Even if an attacker compromises the Windows kernel, they cannot alter the code integrity checks or modify page-table permissions to mark unsigned pages containing injected code as executable.

Dynamic Code Restrictions

In tandem with signature verification, Windows 10 provides Arbitrary Code Guard (ACG). While CIG ensures that files loaded from disk are signed, ACG prevents an attacker from generating executable code directly in the process's memory (reflective DLL injection). By enforcing that memory pages cannot be simultaneously writable and executable, and preventing modifications to existing executable pages, ACG stops in-memory injection methods where no physical DLL is written to the disk.
