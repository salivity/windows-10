Role of SAM Client in Windows 10 Domain Operations

The Security Account Manager (SAM) client in Microsoft Windows 10 acts as the vital communication bridge between local security processes and remote Active Directory Domain Services (AD DS). While the local SAM database stores and manages local accounts, the SAM client component within the Local Security Authority Subsystem Service (LSASS) routes account queries, resolves security identifiers (SIDs), and coordinates authorization data during domain member operations. This article explores how the SAM client operates when a Windows 10 workstation interacts with an Active Directory domain, focusing on account lookup, local group population, and communication protocols.

Distinguishing Local Storage from Domain Operations

On a standalone machine, the SAM service directly manages the local registry-based security database (SAM hive). However, when a Windows 10 computer joins an Active Directory domain, domain identity management shifts to the Domain Controllers (DCs).

In this environment, the local SAM service relies on the SAM client interface to differentiate between local and domain requests:

  • Local Requests: Queries for accounts local to the machine (e.g., COMPUTERNAME\LocalAdmin) are handled directly by the local SAM database.
  • Domain Requests: When an application or subsystem queries an account within the domain (e.g., DOMAIN\User), the SAM client recognizes that the domain context is not hosted locally and directs the operation to the appropriate domain service or remote DC.

Managing Local Group Nesting with Domain Principals

A primary operational role of the SAM client on a domain member workstation is managing membership in local security groups. Domain administrators frequently add domain users or domain global groups into built-in local groups, such as Administrators, Remote Desktop Users, or Users.

When an administrator manages these groups via the Computer Management console, PowerShell, or the command line (net localgroup):

  1. The administrative tool issues an API call to the local SAM.
  2. The local SAM client contacts a Domain Controller using the Security Account Manager Remote (MS-SAMR) protocol or Lightweight Directory Access Protocol (LDAP).
  3. The SAM client validates the domain account's existence and retrieves its SID.
  4. The local SAM then writes that domain SID into the membership list of the target local group.

Resolving Names and Security Identifiers (SIDs)

The SAM client assists the Local Security Authority (LSA) in translating human-readable account names into binary SIDs, and vice versa (LookupAccountName and LookupAccountSid operations).

When a domain user attempts to access a local resource, the SAM client checks whether the target identifier belongs to the machine or the domain:

  • If the SID has a domain-specific relative identifier (RID), the SAM client, working in tandem with the Netlogon and LSA services, sends the lookup request across the network to a Domain Controller.
  • The returned account details, such as the full user principal name and account status, are supplied back to the local caller for access control evaluation.

Facilitating Access Token Creation During Logon

During an interactive logon on a Windows 10 domain member, authentication is handled primarily by Kerberos or NTLM via the Kerberos Security Support Provider (SSP) or MSV1_0 SSP. However, the SAM client still plays an essential role in authorization and local token compilation:

  1. PAC Extraction: The authentication package receives a Kerberos ticket containing a Privilege Attribute Certificate (PAC) detailing the domain user's domain group memberships.
  2. Local Group Membership Evaluation: The LSA invokes the local SAM to determine which local groups the incoming domain user belongs to—either directly or through nested domain groups.
  3. Token Construction: The local SAM provides the list of local group SIDs to LSASS. LSASS combines these local SIDs with the domain SIDs from the PAC to create the comprehensive access token that governs the user's session rights and resource access.

Network Protocol Implementation (MS-SAMR)

The SAM client implements the client-side stubs of the MS-SAMR (Security Account Manager Remote) protocol over Remote Procedure Calls (RPC), utilizing either named pipes (\pipe\samr over SMB) or TCP/IP dynamic endpoints. Through MS-SAMR, the client can securely query domain-level account policies, password complexity requirements, and lockout statuses when requested by local management interfaces.
