Windows 10 File Lock Handling via Restart Manager

The Windows 10 Restart Manager is an integrated operating system component designed to resolve file lock contentions during software updates and installations without requiring a full system reboot. By programmatically detecting which applications or services hold exclusive locks on targeted files, the Restart Manager coordinates the graceful shutdown, file replacement, and automatic restoration of those processes. This mechanism streamlines system maintenance, reduces downtime, and preserves user application state when resource conflicts occur.

The Problem of File Lock Contention

In Windows, processes frequently open files with exclusive read or write access or map executables and dynamic-link libraries (DLLs) directly into memory. When an installer or updater attempts to modify, overwrite, or delete a locked file, the operating system denies the request with a sharing violation error (ERROR_SHARING_VIOLATION). Historically, installers resolved this by queuing file replacements for the next system boot via the PendingFileRenameOperations registry key. The Restart Manager provides a dynamic alternative to resolve these locks immediately.

Session Initialization and Resource Registration

When an installer or update process begins, it interacts with the Restart Manager through its primary Win32 API functions:

  1. Creating a Session: The installer initializes a session by calling RmStartSession. This generates a unique session handle used to track all subsequent resource queries and actions.
  2. Registering Resources: The installer registers the specific files, folders, or services it needs to modify using RmRegisterResources.

Identifying Blocking Processes

Once resources are registered, the Restart Manager queries the operating system kernel to identify any active processes holding open handles to those files.

By executing RmGetList, the installer retrieves a list of all processes causing lock contention. The API returns detailed process metadata, including process IDs, application names, service statuses, and flags indicating whether an application is Restart Manager-aware.

Process Shutdown and Conflict Resolution

Once the blocking applications are identified, the Restart Manager executes a coordinated shutdown sequence via RmShutdown:

  • Restart Manager-Aware Applications: Applications registered with the Application Recovery and Restart (ARR) API are notified first. They are given a brief window to serialize and save their current state, unsaved documents, and user preferences.
  • Standard GUI Applications: The operating system posts standard WM_QUERYENDSESSION and WM_ENDSESSION messages to top-level windows, allowing the applications to close normally.
  • Windows Services: Services holding locks are signaled through the Service Control Manager (SCM) to stop gracefully.
  • Unresponsive Processes: If an application fails to respond within a defined timeout period, or if the installer specifies forced termination, the Restart Manager terminates the process forcefully using standard process termination routines.

File Replacement and Restoration

With the processes terminated or stopped, the file handles are released, clearing the lock contention. The installer then performs the necessary file operations—such as copying, updating, or deleting files—without facing access violations.

Once the file modifications are complete, the installer calls RmRestart. The Restart Manager reads the stored session context and restarts the terminated applications and services in their original order. If an application supports Application Recovery, it restarts with its previously saved state, allowing the user to resume work seamlessly.

Fallback Behavior

If a critical system process (such as a core operating system component that cannot be terminated safely) holds a lock, the Restart Manager flags the process as non-terminable. In such cases, the system suppresses the shutdown attempt and directs the installer to fall back on scheduling the file replacement upon the next system reboot using MoveFileEx with the MOVEFILE_DELAY_UNTIL_REBOOT flag.
