Windows 10 Device Firmware Updates via Windows Update

This article explains how Microsoft Windows 10 manages, delivers, and applies device firmware updates using the native Windows Update service. By integrating UEFI Capsule Updates, driver packages, and the EFI System Resource Table (ESRT), Windows 10 automates the installation of critical hardware and motherboard firmware, streamlining security patches and system stability improvements without requiring proprietary manufacturer utilities.

Firmware Packaged as Driver Packages

Device manufacturers distribute firmware updates through Windows Update by bundling the firmware binary into a standard driver package. This package typically consists of:

  • An INF file containing metadata, device identification, and installation directives.
  • A firmware payload binary (such as a .bin or .cap file).
  • A security catalog (.cat) file signed by Microsoft to ensure payload integrity and authenticity.

Because Windows treats the firmware payload like a device driver, it can be inventoried, deployed, scheduled, and managed using the existing Windows Update infrastructure, Windows Server Update Services (WSUS), or Microsoft Intune.

Discovery via the EFI System Resource Table (ESRT)

To determine if a firmware update is needed, Windows 10 queries the system's UEFI during startup. The UEFI firmware exposes the EFI System Resource Table (ESRT), which reports:

  • Unique GUIDs for each updatable firmware component (such as system BIOS, embedded controllers, or device peripherals).
  • The currently installed firmware version.
  • The lowest version to which the firmware can be rolled back.
  • The status of the last attempted update.

Windows reads these GUIDs and creates corresponding device nodes in Device Manager under the Firmware category. When Windows Update checks for new updates, it matches these hardware IDs against the Microsoft Update catalog.

Staging the Payload

When a matching firmware update is found, Windows Update downloads the driver package. The Windows installation engine runs the INF file, which uses the UpdateFirmware directive. Instead of writing directly to the hardware flash memory—which could corrupt the system if interrupted—Windows copies the firmware binary into the EFI System Partition (ESP) and calls the UEFI runtime service UpdateCapsule. This operation stages the firmware binary into system memory and flags the UEFI environment that an update is pending upon the next reboot.

Execution via UEFI Capsule Updates

Firmware cannot be fully flashed while Windows 10 is running. When the user restarts the computer:

  1. Windows initiates a standard reboot and passes control to the UEFI firmware.
  2. The UEFI boot manager detects the pending capsule update staged in the EFI partition or memory.
  3. The platform firmware verifies the cryptographic signature of the capsule to ensure it has not been tampered with.
  4. If the signature is valid, the UEFI flashing engine applies the new code to the flash ROM. A manufacturer logo and progress bar are typically displayed to the user during this phase.

Validation and Reporting

Once the flashing process completes, the system restarts again. During the subsequent boot, the UEFI firmware updates the ESRT with the new version number and reports an execution status code (success, invalid signature, insufficient power, etc.).

When Windows 10 loads, the OS reads the updated ESRT. If the update succeeded, Device Manager reflects the new firmware version. If the update failed, Windows logs an event in the Windows Event Viewer and updates the device status accordingly.
