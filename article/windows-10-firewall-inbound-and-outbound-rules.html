Windows 10 Firewall Inbound and Outbound Rules

This article explains how the Microsoft Windows 10 operating system implements and enforces Windows Defender Firewall inbound and outbound rules. It covers the underlying architectural framework, default traffic behaviors, rule evaluation precedence, stateful packet filtering, and the network profile system used to secure incoming and outgoing network traffic.

The Underlying Engine: Windows Filtering Platform (WFP)

Windows Defender Firewall does not filter packets entirely on its own; it relies on the Windows Filtering Platform (WFP). WFP is a set of system services and kernel-mode components built directly into the Windows operating system network stack. When network packets arrive at or depart from a network interface, the OS passes them through WFP filtering layers (such as transport layer, network layer, and application layer enforcement). Windows Defender Firewall acts as the administrative management layer and provider that translates user-defined rules into filtering conditions executed directly in the kernel by WFP.

Default Traffic Posture

Windows 10 operates on an asymmetric default posture for inbound and outbound traffic:

  • Inbound Traffic: By default, all unsolicited inbound connections are blocked unless an explicit inbound rule allows them. This prevents unauthorized access from external hosts.
  • Outbound Traffic: By default, all outbound traffic initiated from the local machine is permitted unless a specific rule explicitly blocks it.

Stateful Packet Inspection

Windows 10 implements stateful packet filtering. The firewall actively maintains a state table of established connections. When an application initiates an outbound connection (e.g., loading a webpage over port 443), the firewall records the session details—including IP addresses and source/destination port pairs. The inbound response traffic matching that established outbound session is automatically allowed back through the firewall, bypassing standard inbound blocking without requiring a dedicated inbound allow rule.

Rule Evaluation and Precedence

When traffic hits the firewall, Windows 10 evaluates rules using a strict hierarchy rather than a top-to-bottom list order. The evaluation order is:

  1. Authenticated Bypass: Rules configured to allow connections specifically authenticated via IPsec (Internet Protocol Security) that override block rules.
  2. Explicit Block Rules: If any rule explicitly blocks the traffic matching the connection criteria, the connection is immediately terminated.
  3. Explicit Allow Rules: If no block rules match, the firewall checks for an explicit allow rule matching the application, port, IP, or protocol.
  4. Default Action: If no rules match the traffic, the firewall enforces the default action configured for the active profile (typically block for inbound, allow for outbound).

Profile-Based Enforcement

Windows 10 assigns each active network interface to one of three network profiles based on Network Location Awareness (NLA):

  • Domain: Applied automatically when the machine is authenticated to an Active Directory domain controller.
  • Private: User-assigned for trusted home or work networks where devices need to discover each other.
  • Public: The default profile for untrusted networks, such as public Wi-Fi hotspots. It applies the most restrictive rules, disabling most local network discovery and file sharing.

Firewall rules can be scoped globally to all profiles or tailored to apply only when a specific profile is active. Multiple network interfaces can operate on different profiles simultaneously.

Rule Criteria and Filtering Parameters

Rules in Windows 10 can evaluate network packets across several parameters simultaneously:

  • Program and Service: Matching the specific executable path (.exe) or Windows Service container initiating or receiving the traffic.
  • Protocol and Ports: Filtering by protocol type (TCP, UDP, ICMP) and specific local or remote port numbers.
  • IP Addresses: Restricting traffic based on local or remote IPv4/IPv6 addresses, subnets, or predefined scopes (such as Local Subnet or Default Gateway).
  • Interface Type: Limiting the rule to Local Area Networks (LAN), wireless networks, or Remote Access/VPN connections.
  • Security (IPsec): Requiring traffic to be authenticated, integrity-protected, or encrypted using Kerberos, certificates, or pre-shared keys.
