What Is the SAM Database in Windows 10?

The Security Account Manager (SAM) database is a critical security component in Microsoft Windows 10 responsible for storing and managing local user account credentials and security identifiers. This article details the primary role of the SAM database, where it resides within the operating system, how it handles local authentication via password hashes, and the built-in safeguards Windows uses to protect it from unauthorized access.

Core Role and Functionality

In Windows 10, the primary role of the SAM database is to facilitate local user authentication. When a user attempts to log into a local account on a non-domain-joined machine—or an offline local fallback account on an enterprise machine—the Local Security Authority Subsystem Service (LSASS) queries the SAM database. SAM verifies the entered credentials against the stored records to either grant or deny access to the operating system.

Credential Storage and Password Hashing

The SAM database does not store user passwords in plain text. Instead, it stores them as cryptographic hashes, predominantly using the NTLM (NT LAN Manager) hashing algorithm. When a user sets or changes a local password, Windows computes the hash and writes it to the SAM file. During subsequent login attempts, the entered password is converted into an NTLM hash and compared against the hash stored in the database. If the hashes match, authentication succeeds.

Management of Security Identifiers (SIDs) and Groups

Beyond storing password hashes, the SAM database maintains the structure of local security principals. This includes:

  • Security Identifiers (SIDs): Unique identifiers assigned to each local user account and group, which Windows uses to manage file permissions and Access Control Lists (ACLs).
  • Local Groups: Standard built-in groups such as Administrators, Standard Users, and Guests, alongside any custom local groups created on the system.
  • Account Policies: Parameters governing local password complexity, expiration limits, and account lockout thresholds.

File Location and Access Restrictions

Physically, the SAM database is stored as a Windows Registry hive located in the directory:

C:\Windows\System32\config\SAM

When Windows 10 boots, the kernel mounts this file into the registry under the key HKEY_LOCAL_MACHINE\SAM.

To prevent tampering and credential harvesting, the operating system locks the SAM file exclusively through the Windows kernel and LSASS, preventing any standard process or user—including the built-in Administrator—from reading, copying, or opening the file directly while Windows is running. Furthermore, the contents of the SAM registry hive are encrypted using a system boot key (historically referred to as SYSKEY), which is derived from the SYSTEM hive to provide an additional layer of protection against offline extraction attacks.

Scope: Local Accounts vs. Domain Environments

The SAM database is strictly limited to local system accounts. In environments where Windows 10 connects to an Active Directory domain or Microsoft Entra ID (formerly Azure AD), authentication is handed off to domain controllers or cloud services using Kerberos or modern identity protocols rather than the SAM database. However, the local SAM database remains active on these systems to host local emergency accounts and manage offline recovery access.
