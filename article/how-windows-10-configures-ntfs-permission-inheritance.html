How Windows 10 Configures NTFS Permission Inheritance

This article explains how the Microsoft Windows 10 operating system manages and applies folder permission inheritance through New Technology File System (NTFS) Access Control Lists (ACLs). It covers the underlying architecture of Access Control Entries (ACEs), the difference between explicit and inherited permissions, how Windows propagates security settings down the directory tree, and how administrators can modify, block, or force inheritance using the graphical user interface and command-line tools.

The Foundation of NTFS Permissions and ACLs

In Windows 10, every file and folder stored on an NTFS volume contains a Security Descriptor. Within this descriptor lies the Discretionary Access Control List (DACL), which is a list of individual Access Control Entries (ACEs). Each ACE defines a specific security principal (such as a user or a security group) and specifies whether access rights—such as Read, Write, Modify, or Full Control—are allowed or denied.

Folder permission inheritance is the automated mechanism that passes these ACEs from a parent directory down to child objects (subfolders and files). This eliminates the administrative burden of manually assigning security rights to every individual file created inside a folder structure.

How Inheritance Works by Default

By default, any new folder or file created within a parent folder automatically inherits the parent's DACL. This behavior is controlled by specific inheritance flags embedded within the ACEs:

  • Container Inherit (CI): Instructs child subfolders to inherit the permission entry.
  • Object Inherit (OI): Instructs child files to inherit the permission entry.
  • Inherit Only (IO): Applies the permission entry solely to child objects, not to the parent folder itself.
  • No Propagate Inherit (NP): Restricts the inheritance to immediate children only, preventing grandchildren folders and files from inheriting the permission.

When a user views the standard "Security" tab under a folder's properties in Windows 10, inherited permissions are visible but typically appear with grayed-out checkboxes, indicating they cannot be modified directly at that specific folder level.

Explicit vs. Inherited Permissions

Windows 10 categorizes permissions into two distinct types:

  1. Explicit Permissions: Access rules applied directly to the specific object. If an administrator manually grants a user "Write" permissions on a subfolder, that entry is explicit.
  2. Inherited Permissions: Access rules cascaded down from a parent folder.

When evaluating permissions, Windows 10 uses a strict order of precedence. Explicit permissions always override inherited permissions. Furthermore, explicit "Deny" entries take precedence over explicit "Allow" entries, which in turn take precedence over inherited "Deny" entries, followed finally by inherited "Allow" entries.

Configuring Inheritance via the User Interface

To manage inheritance settings in Windows 10:

  1. Right-click the target folder, select Properties, navigate to the Security tab, and click the Advanced button.
  2. The Advanced Security Settings window displays the current DACL, including a column labeled Inherited from. This column explicitly identifies whether a rule originates from the parent directory or is locally defined.
  3. At the bottom of the interface sits the Disable inheritance button. Clicking this triggers a prompt with two options:
    • Convert inherited permissions into explicit permissions on this object: Copies all inherited permissions and makes them locally editable, maintaining the existing access state while severing the link to the parent folder.
    • Remove all inherited permissions from this object: Erases all inherited ACEs instantly, leaving only existing explicit permissions (or none, which restricts access to everyone except the object's owner).
  4. If inheritance was previously disabled, an Enable inheritance button appears, allowing the folder to reconnect to the parent's rule set and discard non-conforming local entries.

Enforcing Inheritance Downward

Over time, subfolders may develop permission drift due to manual edits or severed inheritance links. Windows 10 provides a mechanism to force inheritance downward from the parent folder.

At the bottom of the Advanced Security Settings dialog, administrators can check the box labeled "Replace all child object permission entries with inheritable permission entries from this object." When applied, Windows 10 strips away all explicit or broken permissions on all descendant subfolders and files, forcing every child object across the entire directory branch to match the parent's inheritance model.

Managing Inheritance with the Command Line

In addition to the graphical interface, Windows 10 includes the native icacls command-line utility for managing inheritance programmatically:

  • icacls <folder_path> /inheritance:e enables inheritance for the directory.
  • icacls <folder_path> /inheritance:d disables inheritance and converts inherited ACEs to explicit ACEs.
  • icacls <folder_path> /inheritance:r disables inheritance and removes all inherited ACEs entirely.
