Windows 10 on ARM Architectural Capabilities

Microsoft Windows 10 on ARM brings the full Windows operating system experience to energy-efficient ARM64 hardware. This article examines the core architectural pillars of the platform, including its native 64-bit kernel, hardware abstraction layer, runtime binary emulation systems, and specialized CPU scheduling for heterogeneous processor topologies.

Native ARM64 Kernel and System Core

At its foundation, Windows 10 on ARM runs an operating system kernel compiled natively for the ARMv8-A 64-bit architecture (AArch64). The Hardware Abstraction Layer (HAL), native drivers, and critical user-mode system components—including the Windows shell, File Explorer, and core background services—execute directly on the ARM processor without abstraction penalties. This architecture supports standard modern operating system primitives, including 64-bit virtual memory addressing, kernel-level security mitigations, and hardware-enforced virtualization via the ARM hypervisor extensions.

x86 Dynamic Binary Translation (WOW64)

To ensure broad software compatibility with legacy Windows ecosystems, Windows 10 on ARM includes an advanced execution layer within the Windows-on-Windows (WOW64) subsystem designed to run 32-bit x86 applications:

  • Just-In-Time (JIT) Translation: When a legacy 32-bit x86 executable launches, the translation engine converts x86 machine instructions into ARM64 instructions in memory blocks.
  • Instruction Caching: Translated code blocks are stored in an execution cache on disk and in memory. When the application executes the same logic repeatedly, it bypasses the translation phase entirely, significantly lowering execution overhead.
  • Exception and Memory Handling: The architecture maps x86 memory models and hardware flags to corresponding ARM states to ensure that legacy software behaves predictably without manual source modifications.

Compiled Hybrid Portable Executable (CHPE)

To minimize the performance penalty of emulation, Microsoft introduced Compiled Hybrid Portable Executable (CHPE) binaries. Within this model, system libraries and OS-level dynamic link libraries (DLLs) are pre-compiled to run as native ARM64 code while exposing an x86 calling convention. When an emulated 32-bit application calls common Windows APIs—such as drawing UI elements, writing to disk, or making network requests—execution jumps immediately into native code rather than continuing through the software emulator.

Heterogeneous Core Scheduling

Modern ARM processors typically leverage heterogeneous multi-core topologies, such as ARM big.LITTLE or DynamIQ configurations, pairing high-performance cores with high-efficiency cores on a single System-on-Chip (SoC). The Windows 10 kernel scheduler is optimized to recognize these asymmetric compute clusters:

  • Energy-Aware Scheduling: Light background processes, system polling, and telemetry are directed to high-efficiency cores to reduce power draw.
  • Performance Boosting: Foreground user tasks, high-demand calculations, and rendering threads are pinned to high-performance cores dynamically.
  • Dynamic Core Allocation: Workloads seamlessly transition between core types based on real-time execution demand, thermals, and battery states.

SoC Integration and Power Management

Windows 10 on ARM is tightly coupled with modern smartphone-grade SoC architectures, primarily Qualcomm Snapdragon platforms. The architecture natively incorporates interfaces for:

  • Modern Standby (Instant-On): Replaces traditional PC sleep states (S3) with connected low-power modes that allow network-connected data fetching and instant device wake cycles.
  • Integrated Connectivity: Built-in hardware interfaces manage integrated LTE and 5G cellular modems directly within the Windows networking stack.
  • Dedicated Co-Processors: Offloads specific computational tasks—such as cryptography, image processing, and audio rendering—to on-chip DSPs (Digital Signal Processors) and dedicated microcontrollers, reducing overall main CPU load.
