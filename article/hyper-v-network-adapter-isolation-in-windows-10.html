Hyper-V Network Adapter Isolation in Windows 10

Microsoft Windows 10 leverages the Hyper-V Virtual Switch to manage and isolate network adapters by decoupling physical hardware from guest operating systems and the host management partition. By implementing a software-defined Layer 2 network switch, Windows 10 enforces traffic boundaries using dedicated switch types, virtual local area network (VLAN) tagging, Port Access Control Lists (ACLs), and hardware abstraction. This architecture prevents virtual machines from intercepting or manipulating external and host network traffic unless explicitly permitted.

The Virtual Switch Architecture and NDIS

At the foundation of Hyper-V network isolation is the Network Driver Interface Specification (NDIS) filter driver. When Hyper-V is enabled and a virtual switch is created, the physical network adapter is unbound from traditional host protocol stacks. Instead, the physical adapter binds exclusively to the Hyper-V Virtual Switch extension.

All frame processing is routed through the virtual switch. The host operating system communicates through a dedicated virtual network adapter rather than directly with the physical interface, placing the host on equal structural footing with virtual machines. This prevents virtual network interfaces from directly accessing physical hardware registers or sniffing raw physical traffic.

Switch Types and Boundary Enforcement

Windows 10 provides three distinct types of virtual switches, each establishing a specific scope of network adapter isolation:

  • Private Virtual Switch: Restricts communication strictly to virtual machines connected to that specific switch. It has no bindings to physical network adapters and generates no interface for the host operating system, creating an air-gapped virtual segment.
  • Internal Virtual Switch: Restricts network traffic to virtual machines on that switch and a single virtual adapter exposed to the host operating system. It blocks all outbound traffic to the broader physical local network because it lacks an uplink to a physical network adapter.
  • External Virtual Switch: Binds directly to a physical network interface card (NIC). It allows traffic out to the physical network, but isolation is maintained by default; virtual machines cannot see each other's traffic unless broadcasted or routed, and the host can be entirely excluded from using the physical adapter by unchecking the "Allow management operating system to share this network adapter" option.

Layer 2 Isolation: VLANs and Trunking

To isolate virtual adapters sharing the same physical uplink, Hyper-V uses IEEE 802.1Q VLAN tagging. Administrators can assign specific VLAN IDs to individual virtual network adapters in Windows 10.

The Hyper-V switch tags outbound packets with the designated VLAN ID and strips incoming tags before passing data to the VM. Packets lacking the matching VLAN ID are dropped at the switch level. This enforces logical segmentation, preventing virtual machines residing on different VLANs from communicating across the shared switch without an intermediate physical or virtual router.

Port Access Control Lists (ACLs)

Hyper-V includes a port-level security engine that enforces directional filtering directly on the virtual ports of the switch:

  • MAC Address Filtering: Virtual switch ports drop packets with mismatched source MAC addresses unless MAC address spoofing is explicitly enabled.
  • DHCP Guard: Drops incoming DHCP server offer packets from unauthorized virtual machines, preventing malicious VMs from acting as rogue DHCP servers.
  • Router Guard: Discards ICMPv6 Router Advertisement and IPv4 redirect messages originating from unauthorized virtual network adapters to prevent man-in-the-middle attacks.
  • Custom Port ACLs: Configurable via PowerShell, these rules block or allow traffic based on IP addresses, MAC addresses, and transport protocols, restricting packet flow before it leaves the virtual switch layer.
