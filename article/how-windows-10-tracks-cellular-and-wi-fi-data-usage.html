How Windows 10 Tracks Cellular and Wi-Fi Data Usage

Windows 10 features a built-in monitoring framework that actively logs network traffic across every active network adapter, including Wi-Fi, cellular, and Ethernet connections. This system operates at the kernel and service levels, attributing network packets to individual applications over a rolling 30-day window. This article explains the underlying mechanisms Windows 10 uses to track data, differentiate between network types, and enforce data management policies.

The System Resource Usage Monitor (SRUM)

The primary component responsible for logging network consumption in Windows 10 is the System Resource Usage Monitor (SRUM). Operating under the service name srumsvc, this background service constantly collects metrics on system resource utilization, including CPU cycles, disk activity, and network bytes sent and received.

The data gathered by SRUM is written to an Extensible Storage Engine (ESE) database file located at:

C:\Windows\System32\sru\SRUDB.dat

The operating system flushes memory-cached data to this database roughly every 60 minutes or immediately during a system shutdown. This persistent database allows Windows 10 to maintain accurate historical usage records even across system reboots.

Network Driver Interface Specification (NDIS) and Kernel-Level Tracking

To accurately measure raw byte counts, Windows 10 relies on the Network Driver Interface Specification (NDIS) and the Windows Filtering Platform (WFP).

  1. Packet Interception: Network drivers interact with the NDIS layer whenever data packets enter or leave the physical or virtual network interface cards (NICs).
  2. Process Attribution: Using the Windows Filtering Platform, the kernel identifies the unique Process ID (PID) associated with each packet. This binds every inbound and outbound byte to a specific application or Windows background service.
  3. Interface Tagging: Each packet is tagged with the unique identifier of the network adapter handling the traffic. This step ensures that data transmitted through a cellular modem (such as an embedded LTE module or USB dongle) is measured separately from traffic moving through a local Wi-Fi or Ethernet adapter.

Differentiating Network Types and Metered Connections

Windows 10 manages adapters through the Network Location Awareness (NLA) service, which identifies the connection medium and assigns the network profile:

  • Adapter Identification: Windows recognizes physical interfaces as distinct media types (e.g., IF_TYPE_IEEE80211 for Wi-Fi and IF_TYPE_WWANPP or IF_TYPE_WWANPP2 for cellular).
  • Metered Connection Designation: Cellular networks are designated as "Metered" by default to prevent unexpected overages, whereas Wi-Fi networks are unmetered by default. Users can manually toggle the metered status on any Wi-Fi network. When marked as metered, Windows uses the underlying tracking architecture to throttle background OS updates and restrict discretionary app data syncs.

User-Facing Controls and Enforcement

All metrics collected by SRUM and the kernel drivers are aggregated and displayed in the Settings app under Network & Internet > Data usage.

From this interface, users can:

  • View Per-App Consumption: Inspect the total data consumed by specific executables over the previous 30 days, broken down by adapter type.
  • Establish Data Limits: Configure monthly, one-time, or unlimited data thresholds for specific connections (especially cellular), which allows Windows to issue notifications when consumption approaches the preset limit.
  • Restrict Background Traffic: Direct the OS to block background data transfers across all or specific connections, using the Windows Filtering Platform to drop non-essential outbound packets generated by background tasks.
