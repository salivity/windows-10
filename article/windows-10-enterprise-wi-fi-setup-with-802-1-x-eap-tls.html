Windows 10 Enterprise Wi-Fi Setup with 802.1X EAP-TLS

This article provides an overview of how the Microsoft Windows 10 operating system configures and processes enterprise Wi-Fi connections utilizing IEEE 802.1X and Extensible Authentication Protocol-Transport Layer Security (EAP-TLS). It covers prerequisite certificate infrastructure, the manual configuration steps within the Windows network settings, automated deployment methods for enterprise environments, and the underlying TLS handshake mechanism used to establish secure wireless access.

Prerequisites for 802.1X EAP-TLS

EAP-TLS relies on mutual authentication using Public Key Infrastructure (PKI). Before a Windows 10 device can successfully connect to an EAP-TLS network, specific certificates must reside in the Windows Certificate Store:

  • Trusted Root Certification Authority Certificate: Installed in the machine or user Trusted Root Certification Authorities store. Windows uses this to validate the identity of the RADIUS/Network Policy Server (NPS).
  • Client Certificate: Issued to the user or machine (depending on the authentication mode) with the Client Authentication Extended Key Usage (EKU) attribute. It must be stored in the Personal store with its associated private key intact.

Manual Configuration in Windows 10

To configure an 802.1X EAP-TLS Wi-Fi network manually:

  1. Create the Base Profile:
    • Open Control Panel > Network and Sharing Center > Set up a new connection or network.
    • Select Manually connect to a wireless network and click Next.
    • Enter the exact Network Name (SSID).
    • Set Security type to WPA2-Enterprise or WPA3-Enterprise.
    • Set Encryption type to AES and complete the initial prompt.
  2. Configure EAP-TLS Settings:
    • Select Change connection settings on the confirmation window (or access the network properties via the adapter settings).
    • Navigate to the Security tab.
    • Choose Microsoft: Smart Card or other certificate from the network authentication method dropdown.
    • Click Settings to open the EAP-TLS properties:
      • Check Verify the server's identity by validating the certificate.
      • Check the corresponding Enterprise Root CA under Trusted Root Certification Authorities.
      • (Optional) Specify the Fully Qualified Domain Name (FQDN) of the authentication servers under Connect to these servers.
      • Ensure Don't prompt user to authorize new servers or trusted CAs is enabled for strict security.
    • Click OK.
  3. Specify Authentication Mode:
    • In the network profile's Security tab, click Advanced settings.
    • Check Specify authentication mode.
    • Select User authentication, Computer authentication, or User or computer authentication based on network policy.
    • Click OK to save all configuration dialogs.

Enterprise Deployment Methods

In corporate environments, configuring endpoints manually is impractical. Windows 10 supports two primary mechanisms for automated provisioning:

  • Active Directory Group Policy (GPO): Administrators configure wireless network policies under Computer Configuration > Policies > Windows Settings > Security Settings > Wireless Network (IEEE 802.11) Policies. The policy pushes the SSID, authentication types, trusted root authorities, and EAP properties directly to domain-joined devices.
  • Mobile Device Management (MDM / Microsoft Intune): Wi-Fi profiles are pushed using Open Mobile Alliance Uniform Resource Identifier (OMA-URI) settings or pre-built Intune Wi-Fi templates. These profiles map directly to Windows 10 WLAN Profile XML schemas and deploy alongside Simple Certificate Enrollment Protocol (SCEP) or PKCS certificate deployment profiles.

The Authentication Handshake

Once configured, Windows 10 executes the connection through the following stages:

  1. Association: The client associates with the Access Point (AP) at Layer 2. The AP restricts the client to 802.1X control traffic.
  2. Identity Request/Response: The AP sends an EAP-Request/Identity, and Windows responds with an EAP-Response/Identity containing the user or machine identity.
  3. TLS Handshake Initiation: The RADIUS server and Windows 10 negotiate TLS parameters via the AP (acting as the authenticator).
  4. Server Validation: The RADIUS server presents its certificate. Windows validates the server certificate against the root CA specified in the profile.
  5. Client Validation: Windows presents its client certificate. The RADIUS server checks the certificate's validity, revocation status (CRL/OCSP), and mapping to Active Directory.
  6. Key Generation and Access: Upon mutual trust verification, both endpoints independently derive the Pairwise Master Key (PMK). The RADIUS server signals an EAP-Success message to the AP along with the PMK, opening the port to standard network traffic and enabling encrypted 4-way handshake communications between Windows 10 and the AP.
