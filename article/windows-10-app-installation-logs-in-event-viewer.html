Windows 10 App Installation Logs in Event Viewer

Microsoft Windows 10 manages application installation activities through its integrated Windows Event Log architecture, recording deployment, modification, and removal events across dedicated log channels. By capturing data generated by Windows Installer (MSI), modern AppX/MSIX package managers, and third-party executable setups, the operating system provides administrators with a centralized, auditable trail of software changes. This article details the specific log channels, event sources, key event IDs, and retention policies Windows 10 uses to track application installations.

Core Channels for Installation Logs

Windows 10 distributes application setup logs across traditional Windows Logs and dedicated Applications and Services Logs depending on the installer technology used.

The Application Log

The standard Windows Application Log (Application.evtx) serves as the primary location for traditional Win32 software and Windows Installer setups. When an installation package executes:

  • Source: Events generated by Microsoft Installer are categorized under the MsiInstaller source.
  • Function: It captures high-level transaction states, runtime errors, missing prerequisites, and product state changes.

Applications and Services Logs for Modern Deployments

Universal Windows Platform (UWP) and MSIX packages bypass the traditional installer service. Windows 10 directs their telemetry to specialized operational channels located under Applications and Services Logs > Microsoft > Windows:

  • AppXDeployment-Server: Tracks the installation, updating, staging, and removal of packaged applications for individual users or the entire machine.
  • AppxPackagingOM: Records errors and execution states related to the reading and unpacking of app manifests.

Key Event IDs to Monitor

The operating system uses standardized Event IDs to signal specific installation outcomes within the Event Log.

Windows Installer (MsiInstaller) Events

  • Event ID 11707: Denotes a successful installation sequence.
  • Event ID 11708: Indicates an installation failure, often including the error code returned by the package.
  • Event ID 11724: Confirms the successful removal or uninstallation of a program.
  • Event ID 1033: Signals that the Windows Installer configured an application.
  • Event ID 1034: Signals that an application was removed.

Modern Packaging (AppX / MSIX) Events

  • Event ID 854: Indicates the start of a deployment operation (install, update, or remove).
  • Event ID 855: Marks the successful completion of the deployment operation.
  • Event ID 404 / 497: Logs failures during package processing or registration, accompanied by specific HRESULT error codes.

Log File Storage and Retention

Windows 10 manages the physical event files using the Windows Event Log service (eventlog):

  • File System Path: All event logs are stored as binary .evtx files within %SystemRoot%\System32\Winevt\Logs\. The standard installer log is stored in Application.evtx.
  • Capacity and Overwrite Policies: By default, Windows sets maximum size limits (typically 20 MB for standard logs). Once a log reaches capacity, the system handles new events according to the configured retention policy:
    • Overwrite events as needed (oldest first): The default behavior ensuring continuous logging without exhausting disk space.
    • Archive the log when full: Preserves historical data by rotating the file before generating a new one.
    • Do not overwrite events: Requires manual clearing by an administrator when the file reaches maximum capacity.

Querying Installation Logs

Administrators can extract installation records using built-in Windows 10 utilities without third-party software.

Event Viewer (GUI)

  1. Open eventvwr.msc.
  2. Navigate to Windows Logs > Application.
  3. Select Filter Current Log in the Actions pane.
  4. Set the Event sources dropdown to MsiInstaller to isolate desktop application installations.

PowerShell

PowerShell interacts directly with the Event Log infrastructure via the Get-WinEvent cmdlet:

# Retrieve recent successful and failed MSI installations
Get-WinEvent -FilterHashtable @{
    LogName = 'Application'
    ProviderName = 'MsiInstaller'
    Id = 11707, 11708
} | Select-Object TimeCreated, Id, Message

For packaged modern applications:

# Retrieve modern app installation events
Get-WinEvent -FilterHashtable @{
    LogName = 'Microsoft-Windows-AppXDeployment-Server/Operational'
    Id = 855
} | Select-Object TimeCreated, Message
