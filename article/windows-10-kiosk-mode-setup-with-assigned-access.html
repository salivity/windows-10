Windows 10 Kiosk Mode Setup with Assigned Access

Assigned Access is a built-in feature in the Windows 10 operating system that allows system administrators to restrict a designated user account to run only a single application or a strictly controlled set of applications. This article explains how Assigned Access functions, the mechanisms it uses to lock down the operating system environment, the supported kiosk architectures, and the primary methods available to configure it.

Understanding Assigned Access

Assigned Access operates by replacing the standard Windows desktop shell (explorer.exe) with a dedicated execution layer for a specific, non-administrator user account. When the assigned kiosk user signs in, the operating system bypasses the traditional desktop interface, taskbar, Start menu, and File Explorer, immediately launching the designated application in full-screen mode.

The feature protects the underlying operating system by blocking standard exit vectors and system shortcuts, such as Ctrl + Alt + Delete, Alt + Tab, and the Windows key. If the kiosk application crashes or is closed by a user, Assigned Access automatically relaunches it to ensure uninterrupted service.

Kiosk Configurations: Single-App vs. Multi-App

Assigned Access supports two primary operational models depending on the Windows 10 edition and deployment requirements:

  • Single-App Kiosks: The kiosk account runs one Universal Windows Platform (UWP) app or Microsoft Edge full-screen above the lock screen. The user has no access to the desktop, file system, or any other application. This is ideal for digital signage, public browsing terminals, or ticketing systems.
  • Multi-App Kiosks: Available in Windows 10 Enterprise and Education editions, this configuration allows administrators to present a restricted Start menu that exposes only a predefined list of approved Win32 and UWP applications. Administrators define the allowed layout using a custom XML configuration file, blocking access to unauthorized binaries and settings.

Core Mechanisms of System Lockdown

Assigned Access enforces kiosk environments through several integrated Windows subsystems:

  1. Shell Launcher: It replaces the default Windows shell for the designated account, preventing access to the system desktop and taskbar.
  2. Keyboard Filtering: System-level keyboard hooks intercept and disable hardware shortcut combinations that could allow users to open Task Manager, switch tasks, or access the desktop.
  3. Account Isolation: Assigned Access runs under a dedicated standard user account. It prevents the account from modifying system files, accessing the registry, or altering administrative settings.
  4. Automatic Process Recovery: A background watchdog service continuously monitors the designated application's process ID. If the process terminates unexpectedly, the service restarts it immediately.

Methods for Configuring Assigned Access

Administrators can deploy Assigned Access through several administrative interfaces:

1. Windows Settings (Local GUI)

For single-device deployments, the native Windows 10 Settings interface provides a straightforward setup:

  • Navigate to Settings > Accounts > Family & other users.
  • Select Set up a kiosk (Assigned access).
  • Create or select a local standard user account.
  • Select the target UWP application or Microsoft Edge instance to run in the kiosk context.

2. Windows PowerShell

Administrators can script single-app configurations locally or remotely using native cmdlets:

  • Set-AssignedAccess -UserName <AccountName> -AppName <AppUserModelId> binds a local standard account to an installed application package.
  • Clear-AssignedAccess removes the kiosk lockdown from an account.

3. Mobile Device Management (MDM) and Intune

Enterprise environments utilize the AssignedAccess Configuration Service Provider (CSP) through Microsoft Intune or third-party MDM solutions. Administrators upload an XML configuration file defining:

  • The target user account (local, Active Directory, or Microsoft Entra ID).
  • Allowed application package family names (PFNs) or file paths.
  • Start layout definitions and allowed browser URLs.

4. Windows Configuration Designer (Provisioning Packages)

Administrators can generate a .ppkg file containing the kiosk configuration settings. Applying this package via USB drive or network deployment automates kiosk creation during or after system setup without requiring full MDM enrollment.

Prerequisites and Editions

  • Windows 10 Pro: Supports single-app kiosk mode with UWP apps and Microsoft Edge.
  • Windows 10 Enterprise and Education: Support both single-app and multi-app kiosk configurations with Win32 and UWP applications.
  • Account Requirement: The kiosk account must be a standard user account; administrative accounts cannot be bound to Assigned Access.
