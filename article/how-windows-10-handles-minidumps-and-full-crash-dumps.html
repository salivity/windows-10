How Windows 10 Handles Minidumps and Full Crash Dumps

When the Microsoft Windows 10 operating system encounters an unrecoverable kernel-level error—commonly known as a Blue Screen of Death (BSOD) or Bug Check—it executes a structured crash dump mechanism to preserve the state of the system for troubleshooting. This process captures memory contents to disk, producing either compact minidumps or comprehensive full memory dumps based on system configuration. This article examines the internal architecture Windows 10 uses to write these files during a crash and outlines the operational differences between small minidumps and complete memory dumps.

The Crash Dump Mechanism

When a fatal condition occurs, Windows halts standard operations immediately to prevent data corruption. The crash handling process proceeds through distinct phases:

  1. Bug Check Initialization: The kernel invokes KeBugCheckEx, terminating all normal CPU scheduling and standard I/O processing.
  2. Minimal Driver Stack Activation: Because file system drivers may be corrupt or unstable, the kernel bypasses normal disk subsystems. Instead, it activates a specialized, pre-loaded disk dump driver stack (such as dump_diskdump.sys and the appropriate miniport driver).
  3. Writing to the Paging File: The dump driver writes the memory contents directly into the system partition's primary paging file (pagefile.sys). The paging file must reside on the boot volume to enable early-stage writing before the standard storage stack is available.
  4. Post-Reboot Extraction: Upon restarting, the Session Manager subsystem (smss.exe) detects the dump signature inside the pagefile. Windows then extracts the captured data and copies it into a standard .dmp file inside the %SystemRoot% directory (typically C:\Windows). Once extracted, the space inside the paging file is marked as free for normal operating system use.

Small Memory Dumps (Minidumps)

A Small Memory Dump, commonly referred to as a Minidump, records the absolute minimum information required to identify why the crash occurred.

  • Default Directory: %SystemRoot%\Minidump (e.g., C:\Windows\Minidump\*.dmp).
  • Typical Size: Approximately 256 KB to 1 MB.
  • Contents:
    • The Stop code (Bug Check code) and its four diagnostic parameters.
    • The list of loaded and unloaded device drivers.
    • The Processor Context (PRCB) for the processor that initiated the crash.
    • The process and thread control structures (EPROCESS and ETHREAD) for the active thread.
    • The kernel-mode call stack for the executing thread at the time of failure.

Minidumps are lightweight and do not exhaust disk storage, making them suitable for quick triage using tools like WinDbg. However, they do not include memory contents from other running processes or unreferenced kernel pools, which can make diagnosing complex corruption bugs difficult.

Complete / Full Memory Dumps

A Complete Memory Dump records the entire contents of physical RAM at the precise moment of failure.

  • Default Location: %SystemRoot%\MEMORY.DMP.
  • Typical Size: Equal to the size of the computer’s installed physical RAM plus a small metadata header.
  • Requirements: The system requires a pagefile.sys on the boot volume that is at least as large as installed physical RAM plus several megabytes (typically RAM + 1 MB to 257 MB for headers). The boot drive must also have sufficient free space to accommodate the resulting MEMORY.DMP file.
  • Contents:
    • The entire physical memory space, including all kernel-mode memory, driver data, running services, and user-mode application memory.
    • Complete allocation tables, thread environments, and hardware state data.

Complete dumps provide the most comprehensive forensic snapshot available. They allow developers and system engineers to inspect user-mode processes, examine full heap allocations, and trace complex memory corruptions that originate outside the active thread. The primary disadvantages are their massive size, the time required to write them to disk during a crash, and the potential security risk of writing sensitive data from memory into an unencrypted file.

Configuration via Windows 10

Windows 10 provides dump selection through System Properties (sysdm.cpl > Advanced > Startup and Recovery). Administrators can select between:

  • Small memory dump (256 KB)
  • Kernel memory dump (captures kernel and HAL memory only, omitting user space)
  • Complete memory dump
  • Automatic memory dump (Windows manages the pagefile size dynamically to balance efficiency and capture reliability)
  • Active memory dump (filters out hypervisor and unallocated space to optimize full-RAM capture size)

Through these mechanisms, Windows 10 isolates critical state data before hardware components lose power, ensuring diagnostics can be conducted after the machine reboots.
