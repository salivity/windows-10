Windows 10 Interrupt Moderation on Network Cards

Hardware interrupt moderation in Windows 10 is an optimization mechanism that manages how and when a Network Interface Card (NIC) signals the CPU to process incoming and outgoing network packets. By batching network interrupts rather than alerting the processor for every individual packet, Windows 10 balances CPU utilization against network latency. This article explores the architecture behind interrupt moderation, how the Windows Network Driver Interface Specification (NDIS) interfaces with hardware, and how the operating system balances throughput and response times.

The Mechanics of Interrupt Moderation

Every time a network adapter receives a packet, it naturally generates a hardware interrupt—a signal to the processor to pause its current tasks and handle incoming data. Under high-throughput conditions (such as gigabit or multi-gigabit transfers), handling millions of individual interrupts per second causes an issue known as "interrupt storms." This overwhelms the CPU, leading to high system overhead, dropped packets, and degraded performance.

Interrupt moderation (often referred to as interrupt throttling or interrupt blanking) resolves this by forcing the NIC to hold back interrupts until certain criteria are met:

  • Time-based threshold: A hardware timer expires after the arrival of an initial packet.
  • Count-based threshold: A predetermined number of packets accumulate in the NIC's receive buffer.

Once either condition is satisfied, the NIC issues a single interrupt for the entire batch of packets.

How Windows 10 Coordinates with Hardware

Windows 10 manages network communication through the Network Driver Interface Specification (NDIS) 6.x architecture. The operating system does not micromanage the millisecond-to-millisecond hardware timers; instead, it delegates this process to the network adapter's firmware and vendor device driver while providing the execution framework.

When the NIC fires a moderated interrupt:

  1. Interrupt Service Routine (ISR): Windows 10 executes a lightweight ISR directly on the CPU core receiving the hardware interrupt. The ISR quickly acknowledges the hardware, turns off further interrupts from that specific queue, and queues a Deferred Procedure Call (DPC).
  2. Deferred Procedure Call (DPC): The Windows kernel schedules the DPC to run at a lower priority. The DPC processes the entire batch of network packets accumulated in the ring buffer, passing them up the TCP/IP stack.
  3. Interrupt Re-enabling: Once the DPC empties the buffer, it re-enables hardware interrupts on the adapter.

By pairing interrupt moderation with features like Receive Side Scaling (RSS), Windows 10 can also distribute these DPCs across multiple processor cores, preventing a single CPU core from bottlenecking network flow.

Driver Configuration and Dynamic Tuning

Most modern NIC drivers installed on Windows 10 (such as those from Intel, Realtek, or Broadcom) implement dynamic or adaptive interrupt moderation algorithms. Under these algorithms, the hardware monitors network traffic patterns in real time:

  • Low Traffic: The hardware reduces or disables moderation delay to minimize latency for time-sensitive tasks like ping requests or interactive sessions.
  • Sustained Heavy Traffic: The hardware automatically ramps up moderation, maximizing batch sizes to conserve CPU cycles for application processing.

Administrators and users can manually adjust this behavior through the Windows Device Manager under the advanced properties of the network adapter. Settings typically include presets such as:

  • Disabled: Maximizes responsiveness at the cost of high CPU utilization; ideal for ultra-low-latency financial transactions or competitive gaming.
  • Low / Medium / High: Fixed threshold intervals balancing CPU savings and latency.
  • Adaptive: The default and recommended state for general-purpose computing, allowing the NIC firmware and Windows 10 to adjust thresholds on the fly based on current packet rates.
