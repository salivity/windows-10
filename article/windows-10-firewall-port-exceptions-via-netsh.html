Windows 10 Firewall Port Exceptions via Netsh

This article explains how to configure firewall port exemptions in Microsoft Windows 10 using the netsh command-line utility within Windows PowerShell. While modern PowerShell includes dedicated firewall cmdlets, the legacy netsh advfirewall firewall context remains a powerful, universally compatible method for adding, viewing, and removing inbound and outbound port rules to permit network traffic through Windows Defender Firewall.

Prerequisites

To execute firewall modifications, Windows PowerShell must be run with elevated privileges. Right-click the Start menu, select Windows PowerShell (Admin), and confirm the User Account Control (UAC) prompt.

Understanding the Netsh Firewall Syntax

The Windows Defender Firewall is managed in netsh under the advfirewall firewall context. The basic syntax for adding a port exemption rule is:

netsh advfirewall firewall add rule name="<RuleName>" dir=<in|out> action=<allow|block> protocol=<TCP|UDP> localport=<PortNumber>

Key parameters include:

  • name: A unique label for the rule.
  • dir: The traffic direction, either in (inbound) or out (outbound).
  • action: Specifies what the firewall does with matching traffic (allow or block).
  • protocol: The network protocol, usually TCP or UDP.
  • localport: The port number or range of ports to open.

Opening an Inbound TCP Port

To allow incoming traffic on a specific TCP port (for example, port 8080 for a local web service), execute the following command:

netsh advfirewall firewall add rule name="Allow Inbound TCP 8080" dir=in action=allow protocol=TCP localport=8080

Opening an Inbound UDP Port

To permit traffic for applications using UDP (such as DNS, streaming services, or certain games) on port 5050, run:

netsh advfirewall firewall add rule name="Allow Inbound UDP 5050" dir=in action=allow protocol=UDP localport=5050

Opening a Port Range

You can open a consecutive range of ports simultaneously by separating the range boundaries with a hyphen:

netsh advfirewall firewall add rule name="Allow Inbound TCP Range 9000-9010" dir=in action=allow protocol=TCP localport=9000-9010

Restricting Rules by Network Profile

Windows Defender Firewall separates settings into three network profiles: domain, private, and public. To ensure a port is only accessible on secure, private networks, append the profile parameter:

netsh advfirewall firewall add rule name="Allow Private TCP 3000" dir=in action=allow protocol=TCP localport=3000 profile=private

Verifying the Rule

To confirm that the rule has been applied successfully, query the firewall using the rule's specific name:

netsh advfirewall firewall show rule name="Allow Inbound TCP 8080"

This output displays the configured parameters, including status, protocol, port, profiles, and associated actions.

Deleting a Port Exemption

To revoke a port exemption and remove the custom rule from Windows Defender Firewall, specify the rule name with the delete command:

netsh advfirewall firewall delete rule name="Allow Inbound TCP 8080"
