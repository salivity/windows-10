How Windows 10 Handles Open With File Associations

In Microsoft Windows 10, the "Open With" dialog serves as an interactive mechanism for users to direct files to specific applications, either on a one-time basis or by permanently redefining system-wide defaults. When triggered, the operating system queries designated Registry hives to populate compatible applications, interprets the user's selection, and—if configured as a permanent assignment—writes the choice to a cryptographically protected Registry key. This article details the underlying architecture, Registry mechanisms, and security features Windows 10 uses to manage file associations via the "Open With" menu.

The "Open With" Dialog Workflow

When a user right-clicks a file and selects "Open with" (or double-clicks an unassociated file), Windows 10 launches the Open With interface (OpenWith.exe). The dialog presents two distinct operational modes:

  1. One-Time Execution: Selecting an application without checking the "Always use this app to open files" option launches the file in the designated program for that single instance without altering future file associations.
  2. Permanent Association: Checking "Always use this app" instructs Windows to register that application as the default programmatic identifier (ProgID) for that specific file extension across the current user profile.

Populating the Application List

To determine which programs appear in the "Open With" list, Windows 10 queries specific sections of the Windows Registry:

  • OpenWithProgids: Located under HKEY_CLASSES_ROOT\.<extension>\OpenWithProgids, this key lists ProgIDs capable of handling the format.
  • OpenWithList: Found in HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Explorer\FileExts\.<extension>\OpenWithList, this key tracks the history of applications the user has previously selected for that file type.
  • Registered Applications: Applications that declare capabilities under HKEY_LOCAL_MACHINE\SOFTWARE\RegisteredApplications are also evaluated and included if their manifests claim support for the extension.

The UserChoice Mechanism and Hash Protection

Unlike earlier iterations of Windows, where any software program could silently modify file associations by directly writing to the Registry, Windows 10 enforces strict protections to prevent unauthorized hijacking.

When a permanent choice is made through the "Open With" dialog, Windows 10 writes the association to:

HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Explorer\FileExts\.<extension>\UserChoice

Under this key, Windows sets two primary string values:

  • ProgId: The identifier of the chosen application (e.g., Applications\notepad.exe or an registered app identifier).
  • Hash: A unique, proprietary cryptographic hash generated by the operating system.

The hash is calculated using an internal algorithm based on the user's Security Identifier (SID), the file extension, the targeted ProgID, and an internal timestamp. Because only the Windows Shell contains the authorization and specific algorithm parameters to create a valid hash, third-party software cannot successfully write directly to the UserChoice key.

If an external program attempts to modify the ProgId without the matching Windows-generated hash, the operating system detects the tampering. Windows 10 then flags the association as corrupt, resets the file type to its system default handler, and issues a desktop notification stating that an app default was reset.

Execution Resolution

When a file is double-clicked in File Explorer, Windows processes the association in a defined order of precedence:

  1. It evaluates the UserChoice key under HKEY_CURRENT_USER.
  2. It verifies the cryptographic hash.
  3. If the hash is valid, it retrieves the execution command located at HKEY_CLASSES_ROOT\<ProgId>\shell\open\command and launches the target process with the file path as an argument.
  4. If no UserChoice exists or the entry is invalid, Windows falls back to system defaults mapped in HKEY_CLASSES_ROOT\.<extension>.
