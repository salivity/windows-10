Windows 10 Connected Standby Power States Explained

In Microsoft Windows 10, Connected Standby—evolved and formally referred to as Modern Standby or the ACPI S0 Low Power Idle model—replaces the legacy ACPI S3 power state to deliver an instant-on, always-connected experience. This article details how Windows 10 configures these power states, coordinates software execution through system brokers, manages hardware transitions into ultra-low-power idle states via the Power Engine Plugin, and balances energy conservation with background connectivity.

The Shift from ACPI S3 to S0 Low Power Idle

Traditional PC architectures rely on the ACPI S3 state (Suspend to RAM), where the central processing unit (CPU) is completely powered down, execution halts entirely, and system context is preserved solely through self-refreshing RAM. Waking from S3 requires re-initializing the processor, chipset, and peripheral buses, which introduces noticeable latency.

Windows 10 configures Modern Standby by keeping the system in the ACPI S0 working state rather than transitioning to an S3 or S4 sleep state. While the system appears "asleep" with the display turned off, Windows 10 actively manages hardware components and software threads, allowing the platform to drop into an ultra-low-power state while remaining capable of immediate resumption and selective background tasks.

The Phases of the Modern Standby State Machine

Windows 10 controls power states through a multi-stage software and hardware transition sequence:

  1. Screen Off and Preparation: When triggered by a timeout, power button press, or lid closure, the OS turns off the display and initiates the power transition. User-mode inputs are suppressed, and the system begins preparing background workloads.
  2. Software Quiescing: The OS systematically throttles and pauses software activity to prevent unnecessary CPU wakeups. This is governed by two core components:
    • Desktop Activity Moderator (DAM): Suspends execution of traditional Win32 desktop applications, placing them into a quiescent state similar to an app suspension model.
    • Background Infrastructure (BI): Manages Universal Windows Platform (UWP) apps and system services, allowing brokered, short-duration tasks (such as incoming VoIP calls, alarms, or email synchronization) through strictly metered execution windows.
  3. Entering Low-Power Idle: Once background tasks complete their execution phase, Windows 10 instructs device drivers to put their respective hardware blocks into low-power device states (D-states, such as D3hot or D3cold).
  4. Achieving DRIPS (Deepest Runtime Idle Power State): Once all integrated sub-systems, buses, and peripheral controllers achieve their appropriate low-power states, the entire System on Chip (SoC) enters DRIPS. In this state, clock generators are stopped, power rails are lowered or completely gated, and memory remains in self-refresh, minimizing energy draw to levels comparable to legacy S3 sleep.

Hardware Arbitration via the Power Engine Plugin (PEP)

To coordinate the complex low-power states of modern microprocessors and SoCs, Windows 10 relies on the Power Engine Plugin (PEP). The PEP acts as the abstraction layer between the Windows Power Manager and the platform-specific hardware logic (provided by chip vendors such as Intel, AMD, or Qualcomm).

When software constraints are met, the Windows Power Manager notifies the PEP that the OS is idle. The PEP evaluates hardware dependency constraints—verifying that all peripheral devices, interconnects, and functional units are quiescent—and triggers the hardware-level platform power management unit to place the SoC into its deepest low-power sleep state. If an event occurs (such as a timer expiration, a network packet with wake-on-LAN signatures, or a peripheral input interrupt), the PEP coordinates the ramp-up of power rails and system clocks before handing execution control back to the operating system.

Connected vs. Disconnected Operation

Windows 10 allows Modern Standby to be configured in either a "Connected" or "Disconnected" mode:

  • Connected Modern Standby: The networking subsystem (Wi-Fi or cellular modem) maintains an active low-power link layer connection with the access point or cellular network. The OS offloads network keep-alive packets and pattern-matching filters to the network interface card (NIC). The NIC only alerts the host processor when a relevant packet (such as a push notification or remote wake frame) is detected, maintaining real-time connectivity without continuously waking the CPU.
  • Disconnected Modern Standby: Network interfaces are completely powered down during sleep, terminating internet access while the screen is off. The system still benefits from instant-on responsiveness and local background tasks (like alarms), while conserving maximum battery life.

Users and system administrators can configure these behaviors via Windows Settings, Group Policy, or power scheme settings using the powercfg /setdcvalueindex and powercfg /setacvalueindex command-line interfaces. System administrators can also evaluate state transitions, identify blocking drivers, and verify DRIPS residency percentages through diagnostic reports generated using the Windows SleepStudy tool (powercfg /sleepstudy).
