How Windows 10 Manages Update Data Transfers

This article explores how the Microsoft Windows 10 operating system regulates and processes background data transfers during Windows Updates. It covers the core underlying network technologies—specifically Delivery Optimization, the Background Intelligent Transfer Service (BITS), and intelligent bandwidth management protocols—that ensure update packages download efficiently without degrading active network performance for the user.

Delivery Optimization and Peer-to-Peer Caching

Windows 10 primarily utilizes Delivery Optimization (DO) to manage the distribution of Windows Updates, feature upgrades, and Microsoft Store apps. Delivery Optimization is a cloud-managed, peer-to-peer (P2P) client service that minimizes internet bandwidth consumption by allowing devices to source update files from other computers on the local network (LAN) or across the internet, rather than relying solely on Microsoft’s remote data centers.

When an update is required, the Delivery Optimization client communicates with the Microsoft cloud service to locate the closest available sources. Update files are divided into small pieces, and the client can download different pieces simultaneously from local peers and HTTP servers. All downloaded blocks are cryptographically verified using metadata to guarantee authenticity before they are compiled and installed.

Background Intelligent Transfer Service (BITS)

While Delivery Optimization handles bulk payload distribution, Windows 10 also employs the Background Intelligent Transfer Service (BITS) for specific update tasks, metadata exchanges, and environments where peer-to-peer transfer is disabled.

BITS facilitates asynchronous, prioritized transfers using idle network bandwidth. It monitors overall network traffic and only downloads update data when network capacity is not actively demanded by foreground applications (such as a web browser or media stream). If a foreground application requests network resources, BITS automatically scales down or pauses the transfer. Furthermore, BITS natively handles network interruptions, automatically resuming incomplete downloads from the exact point of interruption rather than starting from the beginning.

Low Extra Delay Background Transport (LEDBAT)

To prevent Windows Updates from saturating internet connections, Windows 10 incorporates Low Extra Delay Background Transport (LEDBAT). LEDBAT is an optimized congestion control algorithm implemented within the TCP transport layer.

Unlike traditional TCP, which increases transfer speeds until packet loss occurs, LEDBAT continuously measures network latency (round-trip time). If it detects an increase in queue delay caused by other network traffic, it immediately backs off and throttles the update download rate. This ensures that latency-sensitive tasks, such as gaming, video calls, and voice over IP (VoIP), experience minimal disruption during background updates.

User Controls and Traffic Management

Windows 10 provides built-in policies and user-facing controls to define how background data transfers operate:

  • Bandwidth Throttling: Users can configure download limits within Windows Update Advanced Options. Transfers can be restricted to a percentage of total available bandwidth or an absolute speed measured in megabits per second (Mbps), both for background and foreground downloads.
  • Metered Connections: Setting a Wi-Fi or Ethernet connection as "metered" signals Windows to suppress automatic, non-critical background data transfers. In this mode, Windows pauses update downloads until the device connects to an unmetered network or the user explicitly grants permission.
  • Active Hours: Users can define specific working hours during which Windows automatically reduces the intrusiveness of update tasks and avoids scheduling automatic reboots.
