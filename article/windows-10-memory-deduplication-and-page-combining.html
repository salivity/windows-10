Windows 10 Memory Deduplication and Page Combining

Memory deduplication in Windows 10, technically referred to as page combining, is an architectural feature within the Windows Memory Manager designed to optimize physical RAM usage. By identifying multiple memory pages containing identical contents across different processes, the operating system consolidates them into a single, shared physical page and marks it as read-only. This article explains how Windows 10 detects identical memory blocks, the role of Copy-on-Write (COW) in safely managing modifications, and the operational balance between CPU utilization and memory conservation.

The Concept of Page Combining

Physical memory frequently contains duplicate information, such as identical runtime libraries, replicated data buffers, or common user-interface assets loaded by multiple running applications. In traditional memory models, each process maintains its own independent copy of these identical pages in physical RAM. Windows 10 implements page combining to systematically reclaim this redundant memory by pointing multiple virtual address mappings to a single physical page frame.

The Scanning and Hashing Mechanism

Page combining operates as an asynchronous, low-priority background process managed by the Windows kernel. The process follows several distinct steps:

  1. Candidate Selection: The Memory Manager scans candidate 4 KB physical pages allocated across the system. It primarily targets pages that are clean, private, and not locked for hardware Direct Memory Access (DMA) operations.
  2. Hash Generation: To avoid expensive byte-by-byte comparisons across millions of pages, the system computes a cryptographic or mathematical checksum (hash) of the candidate page's contents.
  3. Hash Table Lookup: Windows maintains an internal hash table of memory pages. The newly computed hash is compared against this table to determine if an identical candidate page already exists in the system.
  4. Byte-Level Verification: If a hash collision occurs, the Memory Manager performs a complete byte-for-byte comparison between the candidate page and the target page to ensure total parity and prevent data corruption.

Merging Pages and Updating Page Table Entries

Once two or more pages are confirmed to be strictly identical, the Memory Manager executes the deduplication step:

  • Remapping: The Page Table Entries (PTEs) belonging to the secondary processes are updated. Their virtual addresses are redirected to point to the primary physical page frame number (PFN).
  • Freeing Redundant RAM: The now-redundant physical memory page is deallocated and returned to the system's free or standby page lists, instantly increasing the pool of available physical RAM.
  • Access Flagging: The shared physical page is marked with read-only permissions across all participating processes.

Managing Modifications via Copy-on-Write (COW)

To maintain process isolation and memory integrity, Windows 10 utilizes the Copy-on-Write (COW) mechanism:

When any process attempts to write to a deduplicated, read-only page, the CPU's Memory Management Unit (MMU) intercepts the operation and triggers a page fault exception (STATUS_GUARD_PAGE_VIOLATION or access violation handled by the kernel). The Windows kernel catches this fault, allocates a new physical 4 KB page, copies the original data into it, applies the intended write operation, and updates that specific process's PTE to point to the newly allocated private page with read-write permissions. Other processes pointing to the shared page remain completely unaffected.

Performance Considerations and CPU Impact

Because scanning, hashing, and page-fault handling consume CPU cycles, the Windows 10 Memory Manager throttles page combining activities. The combining algorithm typically runs during periods of low system activity (idle states) or when the operating system begins to experience memory pressure. By running at a background priority, page combining delivers significant RAM savings—particularly in virtualized desktop infrastructure (VDI) environments and systems running multiple instances of the same application—without degrading interactive desktop performance.
