What Is the Secondary Logon Service in Windows 10?

The Secondary Logon service in Microsoft Windows 10 enables users to run programs, administrative tools, and processes with alternate security credentials without having to log out of their current session. By allowing privileged tasks to be executed from a standard user account, this service plays a vital role in system security, administrative efficiency, and software compatibility.

Core Functionality and "Run As"

The primary function of the Secondary Logon service (internal name seclogon) is to power the "Run as different user" and "Run as administrator" features within the Windows operating system. When a user right-clicks an executable or shortcut and selects an option to run the program under alternate credentials, the Secondary Logon service handles the request. It prompts for the appropriate username and password, authenticates the credentials against the local security authority or domain controller, and launches the application under that specific security context.

Supporting the Principle of Least Privilege

From a security perspective, the Secondary Logon service is a cornerstone of the Principle of Least Privilege (PoLP). Best security practices dictate that users—including system administrators—should operate day-to-day under standard user accounts with limited rights to minimize the risk of malware infections and unauthorized system modifications.

When administrative tasks are required, such as modifying system settings, installing drivers, or running management consoles (like PowerShell or Event Viewer), the Secondary Logon service allows the user to temporarily elevate privileges for only that specific task. The primary desktop environment remains restricted, preventing malicious code from automatically inheriting full administrative control.

Impact on Third-Party Applications and Gaming

Beyond administrative management, several third-party applications rely on the Secondary Logon service to function properly. For example, video game launchers (such as Blizzard's Battle.net) and developer environments often use this service to manage background updates, install patches, or handle multi-user components. If the service is stopped or disabled, these programs may return errors, fail to update, or refuse to launch entirely.

What Happens If the Service Is Disabled?

Disabling the Secondary Logon service directly impacts daily usability and administrative workflows:

  • Loss of "Run as" Capabilities: Users cannot manually execute applications with alternate credentials.
  • UAC Complications: Standard accounts may encounter failures when attempting tasks that require entering administrator credentials through User Account Control (UAC).
  • Application Failures: Programs that depend on secondary authentication mechanisms to launch secondary worker processes will malfunction.

How to Manage the Secondary Logon Service

The service runs through svchost.exe and is backed by the seclogon.dll file. Its default startup type in Windows 10 is typically set to Manual, meaning Windows starts the service only when a process or user requests it.

To check or modify its status:

  1. Press Windows Key + R, type services.msc, and press Enter.
  2. Scroll down and locate Secondary Logon.
  3. Double-click the entry to view its properties.
  4. Set the Startup type to Manual (recommended) or Automatic if dependent applications fail to start it automatically.
