How Windows 10 Dynamic Lock Works with Bluetooth

Windows 10 Dynamic Lock is a built-in security feature that automatically secures your computer when you step away from your desk carrying a paired Bluetooth device, such as a smartphone. By continuously evaluating the Bluetooth connection's signal metrics between the PC and the paired device, the operating system can infer physical proximity. This article explains the technical mechanism behind Dynamic Lock, including Bluetooth pairing, signal threshold monitoring, timeout algorithms, and the execution of the lock command.

The Bluetooth Pairing Foundation

Dynamic Lock relies on a standard Bluetooth pairing between the Windows 10 device and any peripheral device, most commonly a smartphone or smartwatch. During the initial pairing process, the devices negotiate cryptographic keys to establish a trusted, authenticated link. Once paired, the Windows 10 Dynamic Lock service (part of the Windows Hello framework) can identify and register the target device as a proximity sensor.

Continuous Proximity Detection via RSSI

To determine user presence, Windows 10 monitors the Received Signal Strength Indicator (RSSI) of the connected Bluetooth device. The operating system regularly queries the Bluetooth radio driver for the device's RSSI values:

  1. Active Tracking: While the user is near the PC, the Bluetooth radio receives a strong signal, confirming user presence.
  2. Signal Degradation: As the user moves away from the PC, physical distance and physical barriers (such as walls or the user's body) cause the RSSI value to drop significantly.
  3. Out-of-Range Detection: If the user moves far enough, the RSSI drops below a preset threshold determined by the operating system, or the connection breaks entirely due to the device being out of physical transmission range.

The Timeout and Grace Period Algorithm

Windows 10 does not lock the PC the exact second the Bluetooth signal drops below the threshold. To prevent accidental lockouts caused by temporary signal attenuation, radio interference, or packet drops, the system implements a grace period:

  • Periodic Polling: Windows checks the connection status at regular intervals.
  • Absence Confirmation: When the system detects that the paired device has dropped below the signal threshold or disconnected, it starts an internal timer.
  • Grace Period Window: Windows 10 waits for approximately 30 seconds to see if the signal recovers. During this window, it may attempt to send active probe requests to the paired device to re-verify its presence.

Executing the Lock Command

If the paired device fails to respond within the grace period, the Dynamic Lock service triggers an operating system event equivalent to the Windows API call LockWorkStation().

Executing this call immediately switches the active session to the Windows lock screen, requiring the user to authenticate again via PIN, password, or Windows Hello biometrics upon return.

Security Architecture and Limitations

Dynamic Lock is designed as an opportunistic security layer rather than a zero-trust perimeter control:

  • One-Way Automation: Dynamic Lock only locks the computer; it intentionally does not unlock the machine when the device returns into Bluetooth range. Unlocking requires active user authentication.
  • Latency by Design: Because of the RSSI timeout and the 30-second grace period, there is a minor delay between the user walking away and the machine locking, meaning it does not replace the security of manually pressing Windows Key + L.
  • Hardware Independence: The feature uses standard Bluetooth core specifications, meaning it requires no proprietary hardware or specialized smartphone apps to function.
