How Windows 10 Defragments Non-Volatile Drives

Windows 10 automatically maintains non-volatile storage drives through a scheduled background service known as Optimize Drives. Instead of applying a one-size-fits-all approach, the operating system detects the underlying hardware type—distinguishing between mechanical Hard Disk Drives (HDDs) and Solid-State Drives (SSDs)—to apply the appropriate optimization method. This article explains how Windows 10 schedules these tasks, performs traditional defragmentation on magnetic storage, and utilizes TRIM and targeted defragmentation on flash-based storage.

The Optimization Service and Scheduling

Windows 10 manages drive health through the "Defragment and Optimize Drives" utility, which runs as part of the daily Automatic Maintenance routine. By default, the operating system schedules optimization tasks on a weekly basis, executing them when the computer is idle to avoid impacting system performance. If a scheduled run is missed due to the system being turned off or under heavy load, Windows queues the task to execute at the next available idle period.

Handling Traditional Hard Disk Drives (HDDs)

For traditional mechanical hard drives, Windows 10 performs standard file defragmentation. Over time, as files are created, modified, and deleted, the file system writes data in non-contiguous clusters across the spinning magnetic platters.

During the defragmentation process, the operating system:

  1. Analyzes the drive to calculate the percentage of fragmented files.
  2. Moves fragmented file parts into contiguous, sequential storage clusters.
  3. Groups free space together to prevent immediate fragmentation of newly written files.

Consolidating these files minimizes physical read-head movement, which lowers access latency, speeds up file retrieval, and reduces mechanical wear.

Handling Solid-State Drives (SSDs)

Because solid-state media relies on flash memory chips rather than moving parts, file fragmentation does not cause mechanical seek delays. Furthermore, excessive writing degrades flash memory endurance. Consequently, Windows 10 handles SSDs differently:

  • The TRIM Command: Instead of reorganizing data blocks, Windows primarily issues TRIM commands to SSDs. The TRIM command informs the drive's controller which data blocks are no longer considered in use by the file system (such as deleted files). This enables the SSD's internal garbage collection mechanism to clear obsolete blocks in advance, ensuring that future write operations run at maximum speed without requiring a slow "read-modify-write" cycle.
  • Occasional SSD Defragmentation: While regular defragmentation is avoided, Windows 10 will defragment an SSD approximately once per month if Volume Snapshot (System Restore) is enabled, or if file system fragmentation reaches metadata limits. The NTFS file system can only track a finite number of file fragments per file; if an SSD becomes excessively fragmented at the file-allocation table level, write errors can occur. In these specific edge cases, Windows defragments the file system metadata to prevent stability issues.

User Configuration and Automation Control

While Windows 10 automates the entire process based on hardware detection, users retain administrative control over the service. Through the "Defragment and Optimize Drives" interface, users can view the current fragmentation percentage, manually trigger an optimization pass, modify the schedule frequency (daily, weekly, or monthly), or exclude specific drives from automatic maintenance entirely.
