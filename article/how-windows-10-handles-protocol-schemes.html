How Windows 10 Handles Protocol Schemes

This article explains how the Microsoft Windows 10 operating system processes, registers, and manages Uniform Resource Identifier (URI) protocol schemes such as mailto and tel. It covers the underlying Windows Registry framework, the security mechanisms that prevent unauthorized protocol hijacking, the user configuration interface, and the end-to-end execution flow when a protocol link is triggered.

Understanding Protocol Schemes in Windows 10

Unlike standard file extensions (such as .txt or .docx), which bind specific file types to applications, protocol schemes (such as mailto:, tel:, or http:) define actions and resource locations. When a user clicks a mailto: link in a web browser or a document, the operating system does not open a file; instead, it passes the URI parameters directly to the application designated to handle that specific protocol.

Registry Registration and the ProgID System

Windows 10 manages protocol schemes primarily through the Windows Registry. Applications register their ability to handle protocols during installation by creating specific keys:

  1. System and User Capabilities: Applications define supported protocols under HKEY_LOCAL_MACHINE\Software\Clients or within their own application capability keys under HKEY_LOCAL_MACHINE\Software\[Vendor]\[App]\Capabilities\URLAssociations.
  2. Protocol Definitions: The base scheme definition resides in HKEY_CLASSES_ROOT\<protocol> (for instance, HKEY_CLASSES_ROOT\mailto). This key must contain a string value named URL Protocol to signal to the Windows Shell that it is a valid protocol handler.
  3. Command Execution: The registry outlines the exact execution string under shell\open\command, specifying the executable path and passing the URI argument via %1.

The UserChoice Hash Protection

In earlier Windows versions, any application could overwrite default protocol handlers by simply modifying the registry. To prevent unauthorized hijacking, Windows 10 enforces a security layer using a cryptographic hash:

  • Location: User preferences are stored in HKEY_CURRENT_USER\Software\Microsoft\Windows\Shell\Associations\UrlAssociations\<protocol>\UserChoice.
  • Hash Validation: The UserChoice key contains the ProgId of the selected application and a Hash value. This hash is generated using a proprietary Microsoft algorithm tied to the user's SID, the protocol name, the ProgID, and a machine-specific secret.
  • Tamper Prevention: If a program modifies the ProgId directly without generating a valid hash, Windows 10 detects the mismatch, invalidates the setting, and resets the protocol handler to the operating system default (often prompting the user to select an app).

User Configuration: "Choose Default Apps by Protocol"

Users can manually configure how Windows 10 handles schemes via the Settings interface:

  1. Open Settings and navigate to Apps > Default apps.
  2. Scroll to the bottom and select Choose default apps by protocol.
  3. Locate the target protocol (e.g., MAILTO for email or TEL for telephony).
  4. Click the associated program to view compatible installed applications and select the preferred default.

When an application is selected, Windows 10 generates the appropriate UserChoice registry key and cryptographic hash on behalf of the user.

Execution Flow

When a user initiates an action containing a protocol URI:

  1. Invocation: The calling application (e.g., Microsoft Edge or Google Chrome) calls the Windows API function ShellExecuteEx, passing the URI string (e.g., mailto:support@example.com).
  2. Lookup: The Windows Shell checks HKEY_CURRENT_USER\Software\Microsoft\Windows\Shell\Associations\UrlAssociations\<protocol>\UserChoice.
  3. Verification: The OS verifies that the associated hash matches the current system state.
  4. Launch: Windows retrieves the command string mapped to the active ProgId and launches the application process, passing the complete URI into the application's command-line arguments for parsing.

Enterprise Deployment and Group Policy

IT administrators can standardize protocol associations across enterprise environments. Using the Deployment Image Servicing and Management (DISM) tool or Group Policy, administrators export a default association configuration using dism /online /Export-DefaultAppAssociations:defaults.xml.

Within this XML configuration, protocols are defined using the <Association Identifier="mailto" ProgId="Outlook.URL.mailto.15" ApplicationName="Outlook" /> structure. When applied via the Set a default associations configuration file Group Policy setting, Windows enforces these defaults during the user's initial profile creation.
