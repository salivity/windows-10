How Windows 10 Handles HDR Video Color Output

This article provides an overview of how the Microsoft Windows 10 operating system processes, composites, and outputs high-dynamic-range (HDR) video. It examines the Windows Advanced Color pipeline, the transformation of color spaces using scRGB and BT.2020, the coexistence of standard-dynamic-range (SDR) and HDR assets on the desktop, and the communication between graphic drivers, the Desktop Window Manager (DWM), and external HDR-capable displays.

The Advanced Color Pipeline

Prior to the integration of HDR, Windows utilized a legacy color pipeline limited to standard 8-bit integer formats per color channel within the sRGB color space. In Windows 10, activating HDR enables the Advanced Color architecture.

Under Advanced Color, the Desktop Window Manager (DWM) shifts its internal rendering buffer to a high-precision, 16-bit floating-point format (FP16) per color channel using the scRGB color space. The scRGB color space shares the same color primaries as sRGB, but its linear, floating-point coordinates allow values below 0.0 and above 1.0. This design allows Windows to encompass the wide color gamut of ITU-R BT.2020 and luminance levels far exceeding standard monitors (up to 10,000 nits) without clipping.

Processing HDR Video Signals

When an HDR video is played (via apps utilizing Media Foundation, DirectX, or supported web browsers):

  1. Decoding: The video stream—typically encoded in 10-bit HEVC, VP9, or AV1 using the BT.2020 color space and the SMPTE ST 2084 Perceptual Quantizer (PQ) electro-optical transfer function (EOTF)—is decoded via DirectX Video Acceleration (DXVA) on the GPU.
  2. DirectX / Direct3D Swap Chains: Media playback applications create swap chains configured for modern HDR pixel formats, predominantly DXGI_FORMAT_R10G10B10A2_UNORM (10-bit integer PQ) or DXGI_FORMAT_R16G16B16A16_FLOAT (16-bit float scRGB).
  3. Color Transformation: The operating system and GPU driver translate the native PQ/BT.2020 signal into the scRGB workspace for desktop composition, or allow direct full-screen pass-through if the app has exclusive control.

SDR and HDR Coexistence

A primary challenge in desktop environments is displaying standard-dynamic-range content (such as standard applications, web pages, and the taskbar) alongside an HDR video.

Windows 10 resolves this through SDR Content Brightness tone mapping:

  • Traditional SDR elements are mapped onto the scRGB buffer by pinning standard white (sRGB value 255) to a user-adjustable target luminance level (typically between 80 and 480 nits).
  • HDR video simultaneously targets the display's peak brightness capabilities.
  • This prevents SDR desktop elements from appearing excessively bright or washed out while HDR video maintains its extended luminance and color range.

Display Metadata and Signal Output

Windows 10 queries the display’s capabilities through Extended Display Identification Data (EDID) and DisplayID, supported by Windows Display Driver Model (WDDM 2.2 or later). It identifies properties such as maximum luminance, minimum black level, and supported HDR color spaces.

When sending the finalized frame to an external HDR10 display over HDMI 2.0a+ or DisplayPort 1.4+:

  • Conversion to Wire Format: The DWM's scRGB linear buffer is converted back into 10-bit (or 12-bit) YCbCr 4:2:2, YCbCr 4:2:0, or RGB at 4:4:4, utilizing the SMPTE ST 2084 PQ curve and BT.2020 color primaries.
  • Static Metadata Injection: Windows transmits static metadata packets (SMPTE ST 2086), including mastering display color volume, Maximum Content Light Level (MaxCLL), and Maximum Frame Average Light Level (MaxFALL).
  • Hardware Tone Mapping: If the video signal demands higher luminance or a wider color gamut than the display can natively replicate, the display's internal scalar performs tone mapping using the transmitted metadata to prevent highlight clipping and preserve shadow detail.
