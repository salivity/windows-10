How Windows 10 Manages Gaming Monitor Refresh Rates

Microsoft Windows 10 manages display refresh rates through a coordinated pipeline involving the operating system kernel, graphics drivers, the Desktop Window Manager (DWM), and hardware-level communication protocols. By negotiating display capabilities via Extended Display Identification Data (EDID), facilitating direct application control in exclusive modes, and integrating Variable Refresh Rate (VRR) technologies like NVIDIA G-Sync and AMD FreeSync, the operating system ensures smooth visual output, low input latency, and tear-free gameplay across modern high-refresh-rate gaming displays.

Hardware Discovery and Capability Negotiation

When a gaming monitor connects to a PC via DisplayPort or HDMI, Windows 10 queries the display's firmware using Extended Display Identification Data (EDID) or DisplayID. This metadata block reports the monitor's supported resolutions, color profiles, timings, and maximum refresh rates (such as 144Hz, 240Hz, or 360Hz).

The Windows Display Driver Model (WDDM) processes this data through the GPU driver. Users can then select their desired target refresh rate in the Advanced Display Settings, which updates the OS-level timing configuration sent to the GPU's display engine.

The Role of the Desktop Window Manager (DWM)

The Desktop Window Manager (DWM) is the compositing engine in Windows 10 responsible for drawing every window, desktop element, and background application. DWM fundamentally operates at the refresh rate of the primary display.

In older versions of Windows 10, running mixed refresh rate setups (such as a 144Hz gaming monitor alongside a 60Hz secondary display) often forced hardware acceleration to desynchronize, locking the primary monitor to 60Hz whenever GPU-accelerated content played on the secondary screen. Beginning with Windows 10 version 2004 (WDDM 2.7), Microsoft decoupled independent display composition, allowing DWM to render and present frames to each connected monitor at its independent native refresh rate without cross-monitor performance penalties.

Display Modes: Exclusive Fullscreen vs. Borderless Windowed

Windows 10 handles refresh rate management differently depending on the game's presentation mode:

  • Exclusive Fullscreen (FSE): The game bypasses DWM composition entirely. The graphics engine takes direct control of the display pipeline, flipping buffers directly to the screen at the application's targeted refresh rate. This mode guarantees minimal input latency and ensures the display hardware runs at the exact frequency specified by the game's settings.
  • Borderless Windowed and Windowed: The game submits frames to DWM as a standard application window. DWM composites the game frame alongside other desktop applications before scanning out to the monitor. While this mode historically introduced latency and locked output to the desktop refresh rate, modern Windows 10 updates introduced optimized flip models (Hardware Independent Flip or DirectFlip) that allow windowed games to bypass the compositor copy step, achieving performance nearly identical to exclusive fullscreen.

Variable Refresh Rate (VRR) and Adaptive Sync

Traditional display management relies on fixed intervals (V-Sync), where the monitor updates at fixed intervals regardless of when the GPU finishes rendering a frame. For gaming, Windows 10 integrates OS-level Variable Refresh Rate (VRR) support.

Under the Graphics Settings menu, Windows 10 includes a dedicated "Variable refresh rate" toggle. This feature enables the OS to:

  • Dynamically match the monitor's physical refresh rate to the instantaneous frame rate output of the GPU.
  • Eliminate screen tearing without the input lag penalties of traditional V-Sync.
  • Extend adaptive sync capabilities (G-Sync and FreeSync) to games running in borderless windowed mode that do not natively support adaptive sync APIs.

Hardware-Accelerated GPU Scheduling (HAGS)

Introduced in Windows 10 version 2004, Hardware-Accelerated GPU Scheduling (HAGS) offloads the coordination of frame scheduling from the CPU directly to a dedicated scheduling processor on the GPU. By reducing the overhead of high-frequency draw calls, HAGS improves frame delivery pacing to high-refresh-rate monitors, minimizing frame drops, micro-stutters, and presentation queue bottlenecks during demanding gaming scenarios.
