Windows 10 Live Tile Pinning for Apps and Web

Windows 10 supports live tile pinning from both Universal Windows Platform (UWP) applications and web browsers through a unified notification and shell integration architecture. By utilizing the Windows Push Notification Service (WNS), adaptive XML payload templates, and dedicated pinning APIs, the operating system allows developers and webmasters to project real-time, glanceable information onto the Start menu. This functionality enables secondary tiles for specific app content as well as pinned web links that update dynamically without requiring the source application or browser to remain open.

Universal Windows Platform (UWP) App Integration

UWP applications interact with the Start menu through the Windows.UI.StartScreen namespace. Windows 10 allows apps to create two types of tiles: primary tiles, which represent the app itself, and secondary tiles, which deep-link to specific content or sections within the app.

To create a live tile, an application initializes a SecondaryTile object, defining properties such as tile ID, display name, arguments, and visual assets for different tile sizes (Small, Medium, Wide, and Large). Once the user grants permission via a system confirmation prompt, the OS registers the tile into the Start menu database.

Dynamic content delivery is managed using the Windows.UI.Notifications namespace. Developers configure adaptive tile templates using an XML schema that specifies text strings, inline images, and layouts. The operating system handles updates via three distinct methods:

  • Local Updates: The app updates the tile directly using the TileUpdateManager while running.
  • Scheduled Updates: The app schedules local notifications to appear at specified future timestamps.
  • Push Notifications (WNS): Cloud servers send XML payloads through the Windows Push Notification Service directly to the device, updating the tile content silently in the background.

Web Browser Integration and Website Pinning

Windows 10 provides native support for pinning websites as live tiles, primarily integrated through Microsoft Edge. Instead of functioning as basic static shortcuts, web-pinned tiles can poll servers for updates using web standards and Microsoft-specific metadata.

Websites implement live tile functionality by serving an XML configuration file, commonly named browserconfig.xml, or by declaring proprietary <meta> tags within the HTML <head> section:

  • msapplication-TileColor: Sets the background tile color on the Start menu.
  • msapplication-square150x150logo (and related tags): Defines icons for various tile dimensions.
  • msapplication-notification: Specifies the URL of an XML feed that provides dynamic tile updates, along with the polling frequency (e.g., every 30 minutes, 1 hour, or daily).

When a user selects "Pin this page to Start" in Microsoft Edge, the browser registers the site with the Windows 10 shell. The operating system's background notification client then takes over the task of periodically polling the defined XML notification endpoint. The server responds with standard Windows tile XML payloads containing headlines, images, or summaries, allowing the website to update its pinned tile autonomously without relying on background browser processes.

System Rendering and Performance

Windows 10 decouples the execution of apps and browsers from tile rendering. The Start menu runs as a dedicated system process (StartMenuExperienceHost.exe) that caches visual assets and XML payloads locally.

When a tile update arrives via WNS, a periodic web poll, or a background task, the operating system validates the XML schema and updates the local cache. The shell's DirectX-driven compositing engine then animates the tile transitions. This architecture prevents memory leaks and excessive battery consumption, ensuring that multiple dynamic tiles can run concurrently without degrading system performance.
