How to Manage Windows 10 Permissions Using icacls

The Microsoft Windows 10 operating system relies on Access Control Lists (ACLs) to dictate how users and system processes interact with files and folders. The icacls (Integrity Control Access Control List) command-line utility is a native administrative tool that allows users to view, modify, grant, deny, back up, and restore these Discretionary Access Control Lists (DACLs) directly from the Command Prompt or PowerShell. This article explains how Windows 10 processes file permissions through icacls, covering the core permission syntax, practical permission modifications, inheritance handling, and backup procedures.

Understanding Access Control Lists and icacls

In Windows 10, every file and folder on an NTFS or ReFS drive is assigned a security descriptor. This descriptor contains a DACL composed of individual Access Control Entries (ACEs). Each ACE identifies a security principal (a user account, group, or SID) and specifies whether access rights are granted or denied.

The icacls command directly interfaces with the Windows security subsystem to read and manipulate these ACEs. When you run icacls, Windows applies changes immediately to the target object's metadata.

Basic Syntax and Viewing Permissions

To display the current permissions of a file or directory, run the following command in an elevated Command Prompt:

icacls "C:\Path\To\FileOrFolder"

The output displays the path followed by user/group accounts and their associated access masks, represented by standard abbreviation codes:

  • F: Full access
  • M: Modify access
  • RX: Read and execute access
  • R: Read-only access
  • W: Write-only access
  • D: Delete access

Inheritance flags may also be displayed in parentheses:

  • (OI): Object inherit (files inherit this ACE)
  • (CI): Container inherit (subfolders inherit this ACE)
  • (IO): Inherit only (applies to children, not the current container)
  • (I): Inherited from the parent container

Granting Permissions

To grant permissions to a user or group, use the /grant switch:

icacls "C:\TestFolder" /grant UserName:(OI)(CI)M

This command grants the specified user "Modify" permissions on C:\TestFolder, applying the rule to all subfolders (CI) and files (OI) within it.

By default, /grant adds the permission to existing rights. If you want to replace any existing explicit permissions for that user rather than appending to them, use /grant:r:

icacls "C:\TestFolder" /grant:r UserName:(OI)(CI)F

Denying Permissions

Windows security evaluates explicit "Deny" entries before explicit "Grant" entries. To explicitly deny an account access, use the /deny parameter:

icacls "C:\TestFolder" /deny BadUser:(OI)(CI)W

This explicitly blocks write access to BadUser, overriding any inherited or group-based grant permissions that would otherwise allow writing.

Removing Permissions

To remove an existing user's permissions from an object without using an explicit deny rule, use /remove:

icacls "C:\TestFolder" /remove UserName

To remove permissions only if they are inherited or explicitly defined, options such as /remove:g (removes granted rights) or /remove:d (removes denied rights) can be specified.

Managing Permission Inheritance

Windows 10 enables permission inheritance by default, meaning newly created files and subfolders automatically receive permissions from their parent directory. You can manage inheritance using the /inheritance switch:

  • Disable inheritance and copy existing rules:

    icacls "C:\TestFolder" /inheritance:d

  • Disable inheritance and remove all inherited rules:

    icacls "C:\TestFolder" /inheritance:r

  • Enable inheritance:

    icacls "C:\TestFolder" /inheritance:e

Backing Up and Restoring ACLs

Before modifying critical system files or complex directory structures, icacls allows you to export current permissions to an ACL text file and restore them later if needed.

  1. Backup permissions recursively:

    icacls "C:\DataFolder" /save C:\Backup\DataFolder_ACLs.txt /t

    (The /t flag operates recursively through all subdirectories and files.)

  2. Restore permissions:

    icacls "C:\" /restore C:\Backup\DataFolder_ACLs.txt

    Note: When restoring, specify the parent directory of the path that was originally saved.
