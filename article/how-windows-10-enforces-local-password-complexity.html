How Windows 10 Enforces Local Password Complexity

Microsoft Windows 10 enforces complexity requirements for local user accounts through the Local Security Policy management console. When enabled, this feature prevents users from selecting weak, easily guessable credentials by mandating a combination of character types, minimum length standards, and restrictions against using personal account identifiers. This enforcement is handled at the operating system level by the Local Security Authority (LSA) whenever a password is created or modified.

The Enforcement Mechanism

Windows 10 implements password policies via the Local Group Policy Editor (gpedit.msc) or the Local Security Policy console (secpol.msc). The core setting responsible for this behavior is located under:

Computer Configuration > Windows Settings > Security Settings > Account Policies > Password Policy

Within this section, the policy titled "Password must meet complexity requirements" serves as the primary enforcement switch. When set to Enabled, Windows 10 validates any newly entered password against a strict set of programmatic criteria before accepting it.

Complexity Rules and Requirements

When the complexity policy is active, every local user password must satisfy the following conditions:

  1. Character Diversity: The password must contain characters from at least three of the following four categories:

    • English uppercase letters (A through Z)
    • English lowercase letters (a through z)
    • Base 10 digits (0 through 9)
    • Non-alphanumeric characters (special characters, such as !, $, #, %)

  2. Account Name Restrictions: The password cannot contain the user's account name or parts of the user's full display name that exceed two consecutive characters.

  3. Length Thresholds: By default, enabling complexity enforces a minimum length of at least six characters, though administrators can configure the separate "Minimum password length" setting to mandate longer passphrases (e.g., 8, 12, or 14 characters).

Interception and Validation

The enforcement occurs in real time through the Windows Local Security Authority Subsystem Service (LSASS). Whether a user attempts to change their password via the Windows Settings app, the Ctrl + Alt + Delete screen, Computer Management, or the command line (net user), the operating system intercepts the request:

  • The system compares the plain text input against the rules defined by the native password filter DLL (passfilt.dll).
  • If the proposed password fails any of the requirements, the operating system rejects the update immediately and returns an error informing the user that the password does not meet the domain or system complexity requirements.
  • If accepted, the password is converted into a cryptographic hash (NTLM) and committed to the local Security Account Manager (SAM) database; the plain text is discarded.

Complementary Policies

Complexity enforcement is typically paired with other local policies to ensure comprehensive credential security:

  • Enforce password history: Prevents users from rotating between a small set of familiar passwords by remembering past entries.
  • Maximum password age: Forces users to update their credentials after a specified duration.
  • Account lockout threshold: Works alongside password policies to lock the local account after a specified number of invalid logon attempts, neutralizing automated brute-force attacks.
